# The Haskell backend

Design document.
[haskell-backend-plan.md](haskell-backend-plan.md) orders the work.

The Haskell backend turns a resolved model into a Haskell module.
It is called `haskell` in a target block, ships compiled into `tdl` and as `tdl-gen-haskell`, and is implemented in `backend/haskell` on the shared pieces [schema-backends.md](schema-backends.md) describes.

Haskell is the target TDL's type system was drawn from.
Sum types, newtypes, type parameters of any kind, multi-parameter classes, functional dependencies, associated types, and conditional instances each have a direct Haskell spelling, so most of what [go-backend.md](go-backend.md) warns about is generated here.
Where a target has no reason to differ from the Go backend, it does not.

## What it emits

One module per model, `Shop/Billing.hs` for module `Shop.Billing`, under the target's `out`.
The module name is the `module` directive, or else the package's segments with each first letter upper-cased, so `shop.billing` is `Shop.Billing`.
A model with no package and no `module` directive is an error, since a module needs a name.

A module is one file rather than one per declaration, because entities may be mutually recursive and Haskell modules may not import each other in a cycle.
Haskell declarations are order-independent, so the module writes them in source order.

The module exports everything it declares, with no export list.
Every file starts with `-- Code generated by tdl. DO NOT EDIT.`, then the `LANGUAGE` pragmas it uses:

```haskell
-- Code generated by tdl. DO NOT EDIT.
{-# LANGUAGE GHC2021 #-}
{-# LANGUAGE DerivingStrategies #-}
{-# LANGUAGE DuplicateRecordFields #-}
{-# LANGUAGE NoFieldSelectors #-}
{-# LANGUAGE OverloadedRecordDot #-}
{-# LANGUAGE StrictData #-}

module Shop.Billing where
```

`GHC2021` is a pragma rather than left to the consumer's `default-language`, so the module means the same thing under any build.
Further extensions are added only when a construct needs one: `DataKinds` for a class with fields, `TypeFamilies` for an associated type, `FunctionalDependencies` for a functional dependency, `DeriveAnyClass` for `derive`, and `OverloadedStrings` when validation writes a message.
The output needs GHC 9.4 or later.

The backend writes no `.cabal` or `package.yaml`.
The generated module depends on `base`, `text`, `bytestring`, `containers`, and `time`, all of which ship with GHC, plus whatever `foreign` and `derive` name.

## The type mapping

| TDL | Haskell | Why |
| --- | --- | --- |
| `string` | `Text` | `String` is a linked list of characters. |
| `int` | `Int64` | The spec puts no width on `int`, and `Int` is only promised 30 bits. |
| `int32` | `Int32` | |
| `uint32` | `Word32` | |
| `int64` | `Int64` | |
| `uint64` | `Word64` | |
| `float32` | `Float` | |
| `float64` | `Double` | |
| `bool` | `Bool` | |
| `bytes` | `ByteString` | Strict, from `Data.ByteString`. |
| `uuid` | `Text` | `base` has no UUID type, and `uuid-types` is a dependency the backend does not choose for a consumer. See [Foreign types](#foreign-types). |
| `instant` | `UTCTime` | |
| `date` | `Day` | Haskell has a date-only type, unlike Go. |
| `duration` | `NominalDiffTime` | It is what adds to a `UTCTime`. |
| `decimal` | `Rational` | Exact, in `base`, and a superset of decimals. A consumer that wants a decimal type maps it with `foreign` to `Scientific`. |

`Rational` makes `decimal` a number, so `min` and `max` on one are checked, where the Go backend's placeholder string warns.
`uuid` is a placeholder a target block replaces: `uuid => foreign("Data.UUID", "UUID")`.

Collections come from the prelude, so the mapping reads the type constructor:

| TDL | Haskell |
| --- | --- |
| `List<T>`, `[T]` | `[T]` |
| `Set<T>`, `{T}` | `Set T`, from `Data.Set` |
| `Map<K, V>`, `{K -> V}` | `Map K V`, from `Data.Map.Strict` |
| `Option<T>`, `T?` | `Maybe T` |
| `Nullable<T>`, `T \| null` | `Maybe T` |

`T? | null` is `Maybe (Maybe T)`, which keeps the distinction where both are written.
A lone `T?` and a lone `T | null` generate the same type, since Haskell has no wire to tell them apart on.

`Set` and `Map` need `Ord` on the element and the key only where a value is built, and every type the backend generates derives `Ord` (see [Deriving](#deriving)), so no set element or map key is refused.

## Structs

Entities, values, and mixins all lower to `ir.Struct`, and each is a record with one constructor named after the type:

```haskell
-- | An order, identified by its id.
data Order = Order
  { id :: Text
  , createdAt :: UTCTime
  , updatedAt :: UTCTime
  , items :: [LineItem]
  , note :: Maybe Text
  , shipOn :: Maybe Day
  }
  deriving stock (Eq, Ord, Show, Generic)
```

Fields are named as the model names them.
Haskell's record fields are module-wide functions, so two records with an `id` field, or an `id` field and the `id` in `Prelude`, would collide.
`NoFieldSelectors` stops a field from being a function, `DuplicateRecordFields` lets two records share a field name, and `OverloadedRecordDot` reads one as `order.id`.
The alternative, prefixing every field with its type's name as in `orderId`, produces names a consumer cannot read from the model.

Fields are strict, through `StrictData`, so a generated value holds no unevaluated thunk.
A `lazy` field directive writes `~` on the one field that needs laziness, such as a reference closing a cycle the consumer ties.

A mixin is a record of its own, since a consumer may name it, and an including record carries its fields directly rather than holding one, as lowering already copied them.

An entity and a value generate the same code until a `key` directive names the fields identifying the entity.
A key naming one field is a function returning it:

```haskell
userKey :: User -> UserId
userKey u = u.id
```

A key naming several fields is a record and a function returning it:

```haskell
data LineItemKey = LineItemKey {order :: Order, sku :: Sku}
  deriving stock (Eq, Ord, Show, Generic)

lineItemKey :: LineItem -> LineItemKey
lineItemKey l = LineItemKey {order = l.order, sku = l.sku}
```

The function is the type's name with its first letter lower-cased and `Key` appended.
A key record derives `Ord`, so a consumer can write `Map LineItemKey LineItem`.

## Enums

An enum is a sum type, and a variant is a constructor.

A fieldless enum also derives `Enum` and `Bounded`, so a consumer can list every variant:

```haskell
data Status = Draft | Placed | Provisional
  deriving stock (Eq, Ord, Show, Read, Enum, Bounded, Generic)
```

A variant with fields is a record constructor:

```haskell
data Payment
  = Card {last4 :: Text}
  | Cash
  deriving stock (Eq, Ord, Show, Generic)
```

A field shared by two variants of one enum must have one type, since Haskell gives the enum one field of that name.
Two variants spelling a field the same with different types warn, and the enum is skipped; `name` on either field resolves it.

Under `OverloadedRecordDot`, `payment.last4` on a `Cash` is a runtime error, as a selector would be.
Pattern matching is total, and is how a consumer is expected to read a variant.

Constructors share one namespace across a module, and so do a record's constructor and a variant.
A variant named like another variant or another record warns at the later declaration, which is skipped.
`name` renames the variant, and `prefix`, on an enum or the target block, writes every variant as the enum's name followed by its own, as in `StatusDraft`.
Prefixing is not the default because the unprefixed spelling is the one a Haskell programmer writes.

## Newtypes and aliases

A newtype is a `newtype`:

```haskell
newtype Email = Email Text
  deriving stock (Eq, Ord, Show, Generic)
```

Its constructor is exported, so a consumer can build one without checking it; a `where` constraint adds the smart constructor [Validation](#validation) describes.

An alias is a `type` synonym rather than an expansion, since Haskell synonyms are transparent as TDL's are and keep the model's name readable in a signature.
A parameterized alias is a parameterized synonym, `type Pair k v = Map k v`.

## Generics

A type parameter is a Haskell type variable, with its first letter lower-cased, so `Page<T>` is `data Page t`.
A parameter whose kind is not `type` carries a kind signature, `data Collection (f :: Type -> Type) t`.

Haskell expresses every kind TDL infers, so a higher kind generates:

```haskell
data Collection f t = Collection {items :: f t}

deriving stock instance (Eq (f t)) => Eq (Collection f t)
```

A declaration with a higher-kinded parameter derives through standalone deriving with the context written out, because stock deriving cannot infer `Eq (f t)`.

A parameterized declaration also derives `Functor`, `Foldable`, and `Traversable` over its last parameter when that parameter appears only where those classes can map it: directly, in a list, a `Maybe`, a map's value, or another generated declaration's last parameter that derives them.
This is decided across the whole model before rendering, as the Go backend decides `comparable`, since a declaration may hand its parameter to one declared after it.

A parameter whose lower-cased spelling is a Haskell keyword, or collides with another parameter of the same declaration, warns and skips its declaration.

A `unit` kind waits on phase 6 of [haskell-backend-plan.md](haskell-backend-plan.md).

## Classes

A TDL class is a contract its satisfying types declare, and so is a Haskell class.
A class is a type class whose superclasses are the classes it requires and one `HasField` constraint per field it requires:

```haskell
class (Timestamped a, HasField "createdAt" a UTCTime, HasField "updatedAt" a UTCTime) => Auditable a

instance Auditable Order
```

A satisfying declaration gets an empty instance, which compiles only when the declaration has the fields.
A field is required through `HasField` rather than a method, because a method is a module-wide name and two classes requiring `createdAt` would collide.

The compiler does not check that a satisfying type has its class's fields, and GHC does.
So the backend checks each instance, and one whose type lacks a required field, or holds it at another type, warns and is not generated.
The spec's own conditional instance, `instance <T> Auditable<Page<T>> requires Auditable<T>`, is one: `Page` has no `createdAt`.

The rest of the spec's class features map directly:

| TDL | Haskell |
| --- | --- |
| `class Container<f: type -> type>` | `class Container (f :: Type -> Type)` |
| `class Projection<from, to> \| from -> to` | `class Projection from to \| from -> to` |
| `type Cursor` in a class | `type Cursor a` |
| `instance Projection<Order, OrderSummary>` | `instance Projection Order OrderSummary` |
| `type Cursor = OrderCursor` in an instance | `type Cursor OrderList = OrderCursor` |
| `instance <T> Auditable<Page<T>> requires Auditable<T>` | `instance (Auditable t) => Auditable (Page t)` |
| `class C<T> requires D<T>` | `class (D t) => C t` |

A class declared without parameters takes one in Haskell, named `a`, or the first unused of `b`, `c`, and so on when a field type spells `a`.
The spec allows a separate instance only in the package declaring the class or the type, which is Haskell's rule against orphan instances, so a generated instance is never an orphan.

`requires` on a struct, enum, or newtype has no place on the type, since Haskell deprecated datatype contexts.
It is written on every function the backend generates for the type, and warns once at the clause, because a consumer can build an `Envelope Int` the model forbids.

`Entity` is the prelude's and is not generated, so `requires Entity<T>` and `class Auditable requires Entity` warn and are emitted without it, as in Go.

## Deriving

Every record, enum, and newtype derives `Eq`, `Ord`, `Show`, and `Generic` with the `stock` strategy, and a fieldless enum adds `Read`, `Enum`, and `Bounded`.
Each primitive's mapping has all four instances, and so does every collection over types that have them.

`Generic` is what lets a consumer write `instance ToJSON Order` in one line.
`derive("Data.Aeson", "ToJSON")`, on a declaration or the target block, adds an `anyclass` instance instead, importing the class from the module named.
It is repeatable, and on the target block it applies to every declaration.

A foreign type is assumed to have the four instances, as Go assumes a foreign type is comparable; a mapping that is wrong about it fails at the consumer's build.

## Validation

`where` constraints are a pair of functions beside the type they check:

```haskell
validateEmail :: Email -> [Text]
validateEmail = validateEmailAt "Email"

validateEmailAt :: Text -> Email -> [Text]
validateEmailAt path (Email v) =
  [path <> ": length(3..254): got " <> Text.pack (show n) | let n = Text.length v, n < 3 || n > 254]
```

`validate<Name>` returns every violation, empty when the value is valid.
`validate<Name>At` threads the path a container prefixes, so a message reads `Order.items[1].quantity: max(100): got 200`, and is exported so a module importing the type can check a field holding it.
As in Go, a message never echoes a string's or bytes' contents.

A constrained newtype also gets a smart constructor:

```haskell
mkEmail :: Text -> Either [Text] Email
```

The constructor stays exported, because hiding it would also hide it from pattern matching and from the consumer's own decoders.

| Constraint | Checks |
| --- | --- |
| `min`, `max` | An integer, a float, or a `decimal`, compared |
| `length` | A string's characters, or the length of bytes, a list, a set, or a map; an integer means exactly that length |
| `oneOf` | A string, integer, or bool equal to one argument, or a fieldless enum's variant named by one |
| `unique` | A list's elements, with `nubOrd`; a set is unique already |
| `matches` | Warns; see below |

`base` has no regular expressions, and each Haskell regex library has its own dialect, so a pattern cannot be checked at generation time against the engine that will run it.
`matches` warns and the rest of the type's constraints are generated.

A type validates the values it holds, at any depth, as in Go.
A newtype checks the set the compiler accumulated down its chain, in one place.
A record with nothing to check gets neither function, and a container holding it does not call one.

A generic type checks its own fields and not its type arguments' values, since checking a `t` would need a class the backend would have to define in every module.

## Foreign types

`Money => foreign("Data.Money", "Money")` says a declaration is a type another module declares.
The generated module imports it and declares nothing for it.
A primitive is a declaration like any other, so `uuid => foreign("Data.UUID", "UUID")` and `decimal => foreign("Data.Scientific", "Scientific")` map the placeholders.

Two arguments, the module and the type, keep `foreign` the same shape it has in the Go backend.

A foreign declaration takes type arguments like any other.
A `where` constraint on a foreign type warns, since the backend does not know what the type holds.
A `key` on one warns, since the key function needs the type's fields.

An extern, a declaration an imported TDL package owns, is the type that package's module declares when the dependency's `ir.Import` carries a `haskell` target block: the module is that block's `module` directive or else the dependency's package, upper-cased the same way.
An extern with neither a `foreign` mapping nor a `haskell` block on its dependency warns and is skipped, and so is each declaration naming it.

## Imports

Every import has an explicit list, `import Data.Text (Text)`, and so does `Prelude`, so a model's `Ordering` or `Either` shadows nothing.
A declaration named like something an import lists makes that import qualified, with the module's last segment as its alias: a model declaring `Text` gets `import Data.Text qualified as Text` and writes `Text.Text`.
An alias taken by another import adds the segment before it, as Go's aliasing does.
Functions the validation code calls, such as `Text.length`, come through a qualified import, so they never meet a model's names.

## Directives

The backend declares all of these in its handshake.

| Directive | On | Does |
| --- | --- | --- |
| `module("Acme.Billing")` | the target block | the module name, and so the file's path |
| `name("Account")` | a declaration, field, or variant | the Haskell identifier, without renaming the model |
| `foreign("Data.UUID", "UUID")` | a declaration | the module and type it maps to, under [Foreign types](#foreign-types) |
| `key(order, sku)` | an entity | the fields identifying it, under [Structs](#structs) |
| `derive("Data.Aeson", "ToJSON")` | a declaration or the target block, repeatable | an `anyclass` instance, under [Deriving](#deriving) |
| `prefix` | an enum or the target block | writes variants with the enum's name in front |
| `lazy` | a field | a lazy field under `StrictData` |

A directive the backend does not declare is a compiler warning and is passed through anyway.

## Names

A declaration's identifier is its name's last segment with the first letter upper-cased, since Haskell requires it of a type and a constructor.
A field keeps its spelling with the first letter lower-cased.
There is no case conversion beyond the first letter, so `httpURL` stays `httpURL`.

A field or parameter spelled like a Haskell keyword gets `_` appended, so `type` is `type_`: `case`, `class`, `data`, `default`, `deriving`, `do`, `else`, `forall`, `foreign`, `if`, `import`, `in`, `infix`, `infixl`, `infixr`, `instance`, `let`, `module`, `newtype`, `of`, `then`, `type`, and `where`.
A name an escape would collide with, as `type_` beside an escaped `type`, warns and skips its declaration.

A generated function, such as `validateEmail` or `mkEmail`, cannot collide with a declaration, since a function starts lower-case and a declaration does not.
A key record can: a declaration named `LineItemKey` beside a multi-field key on `LineItem` warns, and the entity is emitted without its key.
A field cannot collide with a generated function either, since under `NoFieldSelectors` a field is not a function.

## Deprecation and documentation

A doc comment becomes a Haddock comment, `-- |` before a declaration or variant and `-- ^` after a field.
A deprecated declaration, variant, or field gets `{-# DEPRECATED Order "use NewOrder" #-}`, so GHC warns at each use, a field's through record dot, construction, and patterns alike.
The pragma names a field by its label alone, so a deprecated field whose label another record in the module shares carries its reason in its Haddock comment only.

## Diagnostics

These warn with the node's position, and the declaration reaching one is skipped: an extern with no mapping, a unit-typed field until phase 6, a parameter or field whose name cannot be escaped, a constructor collision, and a field two variants spell with different types.
`emit.Cascade` then skips every declaration naming a skipped one.

These warn and the declaration is still emitted: an instance whose type lacks a field its class requires, `matches`, a `where` constraint the backend gives no meaning to, a `requires` clause on a type, a `requires` naming `Entity`, and a `key` the backend cannot generate.

An error stops the run, and only a module name Haskell refuses earns one.

## Checking the output

The tests type check every response with `ghc -fno-code -Wall -Werror` when `ghc` is on `PATH`, since generated code that compiles with warnings is noise in a consumer's build.
`checks.gen-haskell` always does, over `testdata/gen/smoke`, with `ghc` from nixpkgs.

The backend does not run a formatter; its layout is fixed and stable, so a regenerated module diffs only where the model changed.

## Reverse

No reverse backend is planned.
Reading Haskell takes a Haskell parser, which in practice is GHC, and [reverse.md](reverse.md)'s round trip needs one in Go.

## Open questions

- **Class fields.** The compiler accepts a satisfying type that lacks its class's fields, and the spec's conditional-instance example relies on it.
  Either a class's fields bind every satisfying type, and the compiler should check them as GHC will, or a conditional instance means the fields are reached through the parameter, which no target spells; the backend warns until the spec says.
- **Units.** See phase 6 of the plan.
- **`requires` on a type.** A GADT constructor carrying the constraint, `Envelope :: Auditable t => ... -> Envelope t`, would enforce what the warning reports, at the cost of standalone deriving on every constrained type.
- **Defaults.** `Field.default_value` is not read. A `default<Name>` value exists only when every field has a default, which is rare enough that a partial record function may serve better.
- **Serialization.** `Generic` and `derive` leave JSON to the consumer, as Go's `tag` does. Generating `aeson` instances that honour TDL's wire conventions, such as a fielded enum discriminated on `kind`, would match the TypeScript and JSON Schema backends and is a commitment to `aeson`.
