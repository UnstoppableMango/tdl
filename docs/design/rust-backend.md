# The Rust backend

Design document.
[rust-backend-plan.md](rust-backend-plan.md) orders the work.

The Rust backend turns a resolved model into a Rust library crate.
It is called `rust` in a target block, ships compiled into `tdl` and as `tdl-gen-rust`, and is implemented in `backend/rust`.

Rust has most of what TDL draws from Haskell and ML: sum types, newtypes that cost nothing, traits with associated types, impls conditional on their parameters, and a `match` the compiler checks for exhaustiveness.
It adds one thing no other target has, privacy that a value cannot get around: a struct whose field is private can be built only by code in its own module, and Rust has no reflection or zero value that reaches past it.
A deserializer is code in that module too, so a derived `Deserialize` would write the field unchecked; the backend never derives one on a checked type, and writes one that goes through the check instead (see [Serialization](#serialization)).
So this backend puts every `where` constraint into a type, as [java-backend.md](java-backend.md) puts it into a constructor, and there is no `validate` method anywhere in the output.
[Constraints](#constraints) says how, and what it costs.

It has no higher kinds and no garbage collector, and each of those absences shapes a section below.

Where Rust has no reason to differ from [haskell-backend.md](haskell-backend.md), the nearest relative in its type system, it does not.

## What it emits

A library crate per model under the target's `out`: `Cargo.toml` and `src/lib.rs`.

```text
out/
  Cargo.toml
  src/lib.rs
```

The whole model is one file, as in Haskell, since Rust items are order-independent and a crate may hold mutually recursive types in one module.
A regenerated file still diffs only where the model changed, because declarations are written in source order.

The crate is named by the `crate` directive, or else by the package's segments joined with `-`, so `shop.billing` is `shop-billing` and is imported as `shop_billing`.
A model with no package and no `crate` directive is an error, since a crate needs a name.

`layout("module")` writes `<name>.rs` alone, with no `Cargo.toml`, for a consumer who declares it as a module of a crate they already have.
Its header then lists the dependencies the consumer's manifest must carry, since a module cannot declare them.

Every file starts the same way:

```rust
// Code generated by tdl. DO NOT EDIT.
#![forbid(unsafe_code)]
#![allow(non_camel_case_types, clippy::upper_case_acronyms, clippy::large_enum_variant)]
```

Under `layout("module")` the module file starts with the same inner attributes, which apply to that module as they would to a crate.
The two naming lints are allowed because a type keeps the model's spelling (see [Names](#names)), and rustc would warn on `Line_Item` and Clippy on `URL`.
`large_enum_variant` is allowed because boxing a variant is a representation choice the model does not make; the `boxed` directive makes it where a consumer wants it.

Every path the generated code names outside the crate is absolute, `::std::string::String` and `::core::cmp::Ord`, so a model declaring `Option`, `String`, or `Result` shadows nothing.
The examples below drop the prefixes for reading.

The manifest is edition 2024 with `rust-version = "1.85"`, the release that stabilized the edition, and lists only the crates the output names:

```toml
# Code generated by tdl. DO NOT EDIT.
[package]
name = "shop-billing"
edition = "2024"
rust-version = "1.85"

[dependencies]
jiff = "0.2"
uuid = "1"
```

The backend writes no `Cargo.lock`, since a library's lock is its consumer's.

## The type mapping

| TDL | Rust | Why |
| --- | --- | --- |
| `string` | `String` | |
| `int` | `i64` | The spec puts no width on `int`, and every other backend makes it 64 bits. |
| `int32` | `i32` | |
| `uint32` | `u32` | |
| `int64` | `i64` | |
| `uint64` | `u64` | |
| `float32` | `f32` | |
| `float64` | `f64` | |
| `bool` | `bool` | |
| `bytes` | `Vec<u8>` | |
| `decimal` | `rust_decimal::Decimal` | Exact, 28 digits, as in C#; `std` has no decimal. |
| `uuid` | `uuid::Uuid` | `std` has none, and the `uuid` crate is what every other crate's UUID support names. |
| `instant` | `jiff::Timestamp` | An instant with no offset or zone, which is what `instant` means. |
| `date` | `jiff::civil::Date` | |
| `duration` | `jiff::SignedDuration` | Signed, which `std::time::Duration` is not. |

`std` has no date, decimal, or UUID, and every Rust project that needs one depends on a crate for it, so the mapping names the crates rather than placeholders a consumer must replace.
`jiff` covers all three time types with one dependency, and its serde output is RFC 3339 and ISO 8601, the strings [schema-backends.md](schema-backends.md) puts on the wire.
A consumer on `chrono` or `time` maps the three with `foreign`, and phase 7 of the plan ships both as profiles.

A crate appears in `Cargo.toml` only when the output names it, so a model with no `uuid` field does not depend on `uuid`.

Collections:

| TDL | Rust |
| --- | --- |
| `List<T>`, `[T]` | `Vec<T>` |
| `Set<T>`, `{T}` | `BTreeSet<T>` |
| `Map<K, V>`, `{K -> V}` | `BTreeMap<K, V>` |

`BTreeSet` and `BTreeMap` iterate in order, so two equal models serialize to equal bytes, and they need `Ord` where `HashSet` needs `Hash`; every generated type that can derive one can derive the other (see [Deriving](#deriving)).
A set element or map key whose type cannot be `Ord`, which means one holding a float, warns and the declaration is skipped, as Go skips a key it cannot compare.

Absence:

| TDL | Rust |
| --- | --- |
| `T?` | `Option<T>` |
| `T \| null` | `Option<T>` |
| `T? \| null` | `Option<Option<T>>` |

A lone `T?` and a lone `T | null` are one type in memory, as in Haskell, and differ only on the wire, under [Serialization](#serialization).

## Structs

Entities, values, and mixins all lower to `ir.Struct`, and each is a struct with public fields:

```rust
/// An order, identified by its id.
#[derive(Debug, Clone, PartialEq, Eq, Hash, PartialOrd, Ord)]
pub struct Order {
    pub id: Uuid,
    pub created_at: Timestamp,
    pub updated_at: Timestamp,
    pub items: Vec<LineItem>,
    pub note: Option<String>,
    pub ship_on: Option<Date>,
}
```

Fields are public because no field needs guarding: a constraint on a field is carried by the field's type (see [Constraints](#constraints)), so any combination of valid field values is a valid struct.
That keeps struct literals, field access, and destructuring, which a struct with private fields and a constructor taking every field would give up.

A field is the model's name in snake case, `createdAt` as `created_at`, since rustc warns on anything else and the warning would land in a consumer's build.
The conversion is `emit.Snake`, the one every backend shares, and [Serialization](#serialization) writes the model's spelling back on the wire.

A mixin is a struct of its own, since a consumer may name it, and an including struct carries its fields directly, as lowering copied them.

### Recursion

Rust lays a struct's fields out inline, so a type that holds itself, directly or through a cycle, has no size.
The spec allows that between entities, and between any types through an optional.

The backend builds the graph of fields held inline, which is every field but those inside a `Vec`, a `BTreeSet`, or a `BTreeMap`, since those already hold their elements on the heap.
A field whose type is in the same strongly connected component of that graph as its declaration is written `Box<T>`, or `Option<Box<T>>`, and nothing else is boxed.

```rust
pub struct Node {
    pub value: i64,
    pub next: Option<Box<Node>>,
    pub children: Vec<Node>,
}
```

The rule is decided over the whole model before rendering, so which edge is boxed depends only on the model, and adding an unrelated declaration never moves a `Box`.
`boxed` on a field boxes it when the rule would not, for a large variant or a consumer's own reasons.

An entity reference held by value is a copy, not a reference: `LineItem.order` holds an `Order`, not the `Order` another `LineItem` holds.
That is what Go's and Haskell's output does too once a value leaves the process, and [Open questions](#open-questions) weighs `Arc` and keys for references.

### Defaults

Rust has no default field values on stable, so a field's default is an associated function beside the struct:

```rust
impl Order {
    pub fn default_status() -> OrderStatus { OrderStatus::Pending }
    pub fn default_tags() -> BTreeSet<String> { BTreeSet::new() }
}
```

A struct every field of which has a default also gets `impl Default`.
Under `serde`, each defaulted field carries `#[serde(default = "Order::default_status")]`, so a payload omitting it decodes to its default.
A default on a field whose type is checked is checked at generation time and written through the private field, which the generated module can reach; one that fails warns and is dropped, since it could never be held.
A default on a foreign type warns and is dropped.

## Enums

An enum is a Rust enum, and a variant is a variant:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, PartialOrd, Ord)]
pub enum Status {
    Draft,
    Placed,
    #[deprecated(note = "no longer issued")]
    Provisional,
}

#[derive(Debug, Clone, PartialEq, Eq, Hash, PartialOrd, Ord)]
pub enum Payment {
    Card { last4: String },
    Cash,
}
```

A variant's fields are a struct variant's fields, public as every variant field is, and a fieldless variant is a unit variant.
A variant lives in its enum's scope, `Payment::Cash`, so two enums may each have one, and no prefix is needed.
No enum is `#[non_exhaustive]`, since the spec seals an enum and an exhaustive `match` over it is the point.

A generic enum is a generic enum, so `Option<T>` in a replacement prelude would generate as written.

## Newtypes and aliases

A newtype is a tuple struct over its base:

```rust
#[derive(Debug, Clone, PartialEq, Eq, Hash, PartialOrd, Ord)]
pub struct Sku(pub String);
```

An unconstrained newtype's field is public, since there is nothing to protect, and it implements `From<String>` and `From<Sku> for String`.
A constrained one's is private, under [Constraints](#constraints).

A newtype over another newtype holds its parent, `pub struct WorkEmail(Email)`, rather than the parent's base.
So a `WorkEmail` is an `Email` with something added, and it checks only what it adds, since the `Email` it holds was checked when it was built.

An alias is a `pub type`, which Rust makes transparent as TDL's is, and keeps the model's name readable in a signature.
A parameterized alias is a parameterized one, `pub type Pair<K, V> = BTreeMap<K, V>`.

## Constraints

Every `where` constraint is a type the value must be built through, and no value of that type violates it.

A constrained newtype has a private field, and the only ways to make one are the ones the backend writes:

```rust
#[derive(Debug, Clone, PartialEq, Eq, Hash, PartialOrd, Ord)]
pub struct Email(String);

impl Email {
    pub fn new(value: String) -> Result<Self, tdl::Violations> { ... }
    pub fn check(value: &String) -> tdl::Violations { ... }
    pub fn get(&self) -> &String { &self.0 }
    pub fn into_inner(self) -> String { self.0 }
}

impl TryFrom<String> for Email { ... }
impl AsRef<String> for Email { ... }
impl From<Email> for String { ... }
```

`new` checks every constraint before failing, and `tdl::Violations` lists each, so a consumer sees all of them at once.
`check` runs the same checks without building, for a consumer who wants to show a user what is wrong with a value they cannot hold.
There is no `new_unchecked`: the guarantee is that a value which exists satisfies its model, and an escape hatch would make every `Email` a maybe.
The guarantee covers what the backend writes; `derive` and `attribute` are escape hatches a model author trusts, so `derive("Default")` on a checked type would add an unchecked constructor, and it warns (see [Deriving](#deriving)).

A constraint on a field is carried by a type named for the struct and the field, declared beside the struct:

```rust
pub struct LineItem {
    pub sku: Sku,
    pub quantity: LineItemQuantity,
}

pub struct LineItemQuantity(i64);
```

`LineItemQuantity` is a constrained newtype like `Email`, with the same functions.
A variant's field is `<Enum><Variant><Field>`, `PaymentCardLast4`, since a variant field cannot be private and so can only be guarded by its type.
The `newtype` directive on a field names its type instead, `quantity: int where { min(1) }` with `LineItem.quantity => newtype("Quantity")`.
A constraint on an optional field constrains the value inside, so `note: string? where { length(..500) }` is `Option<OrderNote>`.

So a struct is valid when each of its fields is, a container holding a checked type checks nothing again, and there is no validation that walks a model.
A message is the type, the field when the type carries one, the constraint as written, and a detail, `LineItem.quantity: min(1): got 0`, and never echoes a string's or bytes' contents, as in Go.
It cannot carry the path a container would prefix, `Order.items[1].quantity`, for the reason [java-backend.md](java-backend.md#constraints) gives: the `LineItem` was built before any `Order` held it.

| Constraint | Checks |
| --- | --- |
| `min`, `max` | An integer, a float, or a `Decimal`, compared; a float that is NaN fails both |
| `length` | A string's characters, or the length of bytes, a list, a set, or a map; an integer means exactly that length |
| `matches` | A string, unanchored, through the `regex` crate |
| `oneOf` | A string, integer, or bool equal to one argument, or a fieldless enum's variant named by one |
| `unique` | A list's elements, through `Ord` |

A string's length counts `chars()`, which are code points, as `emit.Length` defines it, and not `len()`, which counts bytes.

### Constraints the type states outright

Where the type system can state the constraint itself, the backend writes that type, and there is nothing to check:

| Constraint | Type |
| --- | --- |
| `oneOf("USD", "EUR")` on a string | A fieldless enum, `Usd` and `Eur`, with `as_str` and `FromStr` |
| `length(32)` on bytes | `[u8; 32]` |

A `oneOf` on a string becomes an enum only when every argument's `emit.Pascal` spelling is a distinct identifier; otherwise it is a checked newtype.
An argument that fails another constraint on the same type, such as `"EURO"` beside `length(3)`, warns and is left out, since it could never be held.
`length(N)` on bytes becomes an array for any `N`, since `N` is known when the type is generated.

[Open questions](#open-questions) weighs a const-generic range type for `min` and `max` on integers, which would carry the bounds in the type rather than in a newtype's name.

### Patterns

`matches` is not passed through as written.
The `regex` crate is the closest engine to RE2 any target has, linear time with no backreferences or lookaround, but it differs where RE2 is ASCII: `\d`, `\w`, `\s`, and `\b` are Unicode-aware in Rust, so `\d` matches `٣`.
The backend parses the pattern with `emit.Pattern` and prints the tree in Rust syntax: `\d`, `\w`, and `\s` become explicit ASCII sets, and `\b` and `\B` become `(?-u:\b)` and `(?-u:\B)`, which the crate accepts in a string pattern.
Printing the tree also escapes the class operators `&&`, `--`, and `~~`, which Rust gives a meaning inside a class and RE2 reads as literals.
General categories, scripts such as `\p{Greek}`, POSIX classes, and case folding mean the same in both, and `.` and a negated class match a code point in both.

Each pattern is compiled once in a `static` `LazyLock<Regex>` beside the type that uses it.
A pattern RE2 refuses warns at generation time and its type is emitted without the check.

The `regex` crate is a dependency only when the output has a `matches`.

## Deriving

Every generated type derives `Debug`, `Clone`, and `PartialEq`.
It also derives `Eq`, `Hash`, `PartialOrd`, and `Ord` unless it holds a float, at any depth through the types it names, since `f32` and `f64` implement none of the four.
A fieldless enum and a newtype over a type that is `Copy` also derive `Copy`; a struct does not, so adding a `String` field to one later breaks no caller.

This is decided over the whole model before rendering, as Go decides `comparable`, since a declaration may hold one declared after it.
A type parameter adds nothing to the decision: `derive` already bounds each impl on its parameters, so `Page<f64>` is not `Ord` and `Page<String>` is.

`derive("schemars::JsonSchema")`, on a declaration or the target block, adds one derive; it is repeatable, and on the target block it applies to every declaration.
`attribute("...")` writes an outer attribute verbatim, for what `derive` cannot say.
Both are trusted: the backend cannot see what a derive or attribute expands to, so it cannot promise a checked type stays checked under one.
It warns on the derives it knows build values, `Default` and serde's `Deserialize`, on a checked type, and otherwise passes what it is given through.
A foreign type is assumed to implement all seven, as Go assumes a foreign type is comparable, and a mapping that is wrong about it fails at the consumer's build.

## Identity

`key(id)` on an entity is an inherent method returning the field:

```rust
impl User {
    pub fn key(&self) -> &UserId { &self.id }
}
```

A key naming several fields returns an owned struct declared beside the entity, so a consumer can write `BTreeMap<LineItemKey, LineItem>`:

```rust
#[derive(Debug, Clone, PartialEq, Eq, Hash, PartialOrd, Ord)]
pub struct LineItemKey {
    pub order: Order,
    pub sku: Sku,
}

impl LineItem {
    pub fn key(&self) -> LineItemKey { ... }
}
```

A key field holding a float warns, since the key could not be ordered, and so does a key struct named like a declaration; the entity is emitted without its key.
A field named `key` also takes the method's name, and warns the same way.

## Generics

A type parameter keeps its spelling with the first letter upper-cased, so `Page<T>` is `pub struct Page<T>` and `Projection<from, to>` reads `From` and `To`.
`requires` is a bound, which Rust states and enforces on the type itself:

```rust
pub struct Envelope<T: Auditable> {
    pub body: T,
    pub received_at: Timestamp,
}
```

So `Envelope<i64>` does not compile, where Haskell and Go can only warn that a consumer can build one.
The cost is Rust's: a bound on a type is not implied, so every `impl` block the backend writes restates it, and so must a consumer's generic code over `Envelope<T>`.

A parameter of a higher kind, `f` in `Collection<f, T>`, has no Rust spelling, since a Rust type parameter is always a type.
It warns at the parameter and skips its declaration, and `emit.Cascade` skips what names it.
A parameter of kind `unit` waits on [Units](#units).

## Classes

A TDL class is a contract its satisfying types declare, and so is a trait; of every target, only Haskell's classes come closer.
A class is a trait whose supertraits are the classes it requires and whose methods are getters for the fields it declares:

```rust
pub trait Auditable: Timestamped {
    fn created_at(&self) -> &Timestamp;
    fn updated_at(&self) -> &Timestamp;
}

#[allow(deprecated)]
impl Auditable for Order {
    fn created_at(&self) -> &Timestamp { &self.created_at }
    fn updated_at(&self) -> &Timestamp { &self.updated_at }
}
```

A trait declares only the fields its own class declares, not those of a class it requires, so `order.created_at()` on a `T: Auditable` resolves to one method.
The compiler refuses a conforming type without a field its class requires, at the declaration and at every instance's head, conditional ones included, so every getter the backend writes reads a field that exists and compiles.
Only a struct can satisfy a class with fields, since an enum or a newtype has none, so an enum or a newtype only ever implements an empty trait.
Every impl carries `#[allow(deprecated)]`, since a getter may read a deprecated field and rustc would warn inside the generated file.

Rust's coherence rules accept everything the spec's instances say.
An `impl` is legal in the crate declaring the trait or the crate declaring the type, and the spec allows a separate instance only in the package declaring the class or the type, so with one crate per package no instance is an orphan.
That includes an instance for another package's type and one for a prelude type, which Go, C#, and Java cannot carry:

| TDL | Rust |
| --- | --- |
| `instance Auditable for shipping.Address` | `impl Auditable for ::shipping::Address`, with getters reading its public fields |
| `instance <T> Archived<Page<T>> requires Archived<T>` | `impl<T: Archived> Archived for Page<T> {}` |
| `instance <T> Archived<List<T>> requires Archived<T>` | `impl<T: Archived> Archived for Vec<T> {}` |
| `class C<T> requires D<T>` | `pub trait C: D` |
| `type Cursor` in a class | `type Cursor;` |
| `type Cursor = OrderCursor` in an instance | `type Cursor = OrderCursor;` |

A class's first parameter is `Self` and the rest are the trait's parameters, so `instance Projection<Order, OrderSummary>` is `impl Projection<OrderSummary> for Order {}`.
A class declared without parameters has only `Self`.
A `requires` on a parameter other than the first is a `where` clause on the trait, which Rust does not imply, so a consumer's bound on `T: Projection<U>` restates it.

A functional dependency is an associated type, which is how Rust says one type determines another:

```rust
pub trait Projection {
    type To;
}

impl Projection for Order {
    type To = OrderSummary;
}
```

With `from -> to`, the determining parameters stay `Self` and trait parameters and each determined one becomes an associated type, so a second `impl Projection for Order` is a conflicting impl, as a second instance is a compiler error in TDL.
`Self` is the first parameter of the dependency's left side.
A class with two dependencies whose left sides differ, as `a -> b` and `b -> a`, can carry only one, and warns that it keeps the first.

What a trait cannot carry warns where it was written:

| Case | Result |
| --- | --- |
| A class of arrow kind, such as `Container<f: type -> type>` | Skipped |
| A class reaching itself through what it requires | Skipped, since a trait cannot be its own supertrait |
| A class with dependencies whose left sides differ | Emitted with the first dependency |

The plan is `emit.PlanInterfaces`, which already decides which classes are generated and drops the cyclic ones.
Rust reads every `emit.Refusal` from `Instance` as implementable, since the conditional, prelude-type, and foreign-type cases it names are the ones coherence accepts.

`Entity` is the prelude's, and its satisfying types are known to the compiler, so the crate declares it as `tdl::Entity`, an empty trait, and implements it for every entity it declares and every extern entity it names.
So `requires Entity<T>` is a bound like any other, and `class Auditable requires Entity` is `pub trait Auditable: tdl::Entity`, where Go and C# drop it with a warning.
Each crate's `tdl::Entity` is its own trait, so an entity from a crate this model never names does not satisfy another crate's bound; [Open questions](#open-questions) weighs a shared runtime crate.

## Units

A unit is the one thing Rust carries as precisely as the IR does.
`ir.Unit` holds a quantity reduced to base dimensions, and a const generic can hold each dimension's exponent, so the crate declares one measure type over the model's base units, in declaration order:

```rust
pub struct Measure<T, const KG: i8, const M: i8, const S: i8>(pub T);

pub type Kg<T> = Measure<T, 1, 0, 0>;
pub type N<T> = Measure<T, 1, 1, -2>;
```

`decimal<kg>` is `Measure<Decimal, 1, 0, 0>`, and `decimal<N>` and `decimal<kg*m/s^2>` are both `Measure<Decimal, 1, 1, -2>`, one type as the spec says, with no name needed for the expression.
A named unit is an alias, so a signature reads `N<Decimal>`.
`Add` and `Sub` are implemented for two measures of one dimension, generically over the exponents.
`Mul` and `Div` would add the exponents in the result type, which needs `generic_const_exprs`, unstable in Rust, so they are not generated and a consumer multiplies the inner values.

A parameter of kind `unit` is one const parameter per base dimension, so `type Quantity<u: unit> { value: decimal<u> }` is `pub struct Quantity<T, const U_KG: i8, ...>`.

The exponents are the model's base units, so a dependency declaring its own base units has its own `Measure`, and a unit-typed field crossing the two warns; phase 6 of the plan decides it.
Until that phase, a unit-typed field is its base type with a warning, and the declaration is emitted.

## Serialization

Without a directive, the output carries no serializer and depends on nothing for one.

`serde` on the target block derives `Serialize` and `Deserialize` and writes the attributes that put the JSON wire convention, the one [schema-backends.md](schema-backends.md) describes and the TypeScript and JSON Schema backends write, into the types:

| Construct | Attribute |
| --- | --- |
| A field whose Rust name differs from the model's | `#[serde(rename = "createdAt")]` |
| `T?` | `#[serde(default, skip_serializing_if = "Option::is_none")]` |
| `T \| null` | `#[serde(deserialize_with = "Option::deserialize")]`, which makes the field required where serde would default it |
| `T? \| null` | a `tdl::double_option` adapter: absent is `None`, null is `Some(None)` |
| A fielded enum | `#[serde(tag = "kind")]`, with `#[serde(rename = "...")]` on a renamed variant |
| An unconstrained newtype | `#[serde(transparent)]` |
| A checked newtype | a `Serialize` writing its base, and `#[serde(try_from = ...)]` naming the base, so a decoded value was checked |
| `bytes` and `[u8; N]` | a `tdl::base64` adapter, since the wire carries bytes as a base64 string |

The tag property and each variant's tag come from `emit.Discriminant` and `emit.Tag`, as in every backend writing JSON, so `Payment::Card` is `{"kind": "Card", "last4": "4242"}` whatever `name` says, and `discriminant("type")` on an enum or the target block renames `kind`.
A variant field named like the discriminant warns and the enum is skipped, as in Go.
A oneOf enum writes its strings, and a fieldless enum its variants' model names.
`uuid`, `rust_decimal`, and `jiff` gain their `serde` features, and their output is the convention's strings: a hyphenated UUID, a decimal as a string, RFC 3339, and ISO 8601.

The base64 codec and `double_option` are a few dozen lines in the `tdl` module, so the output needs `serde` and nothing else for it.
Because a checked newtype decodes through `TryFrom`, a deserialized model is valid by construction too, and the decoder's error names the violation.

## Foreign types and externs

`foreign("jiff::civil", "Date")` maps a declaration or a primitive to a type another crate declares, written `::jiff::civil::Date`.
Two arguments, the module path and the type, keep the shape `foreign` has in every backend.
The crate it names must be in the manifest, so `dependency("chrono", "0.4")` on the target block adds one; it is repeatable, and a third argument lists features, `dependency("chrono", "0.4", ["serde"])`.
A `foreign` naming a crate no `dependency` lists and the backend does not already add warns, since the manifest it writes would not build.

A `where` constraint on a foreign type warns, since the backend does not know what the type holds, and so does a `key`.

An extern resolves through its dependency's `rust` target block: the crate is that block's `crate` directive or else the dependency's package, joined the same way.
When that block names an `out`, the manifest depends on it by a relative `path`; otherwise the extern's crate is listed by name alone and warns, since the consumer must say where it is.
An extern with neither a `foreign` mapping nor a `rust` block on its dependency warns and is skipped, and so is each declaration naming it.

TDL's import graph has no cycles, and neither may a crate graph, so one crate per package always builds.

## Directives

The backend declares all of these in its handshake.

| Directive | On | Does |
| --- | --- | --- |
| `crate("shop-billing")` | the target block | the crate's name |
| `layout("module")` | the target block | writes one module file and no manifest |
| `dependency("chrono", "0.4")` | the target block, repeatable | adds a crate to the manifest, with optional features |
| `serde` | the target block | the attributes under [Serialization](#serialization) |
| `discriminant("type")` | an enum or the target block | the tag property under `serde` |
| `name("Account")` | a declaration, field, or variant | the Rust identifier, without renaming the model |
| `newtype("Quantity")` | a constrained field | the name of the type carrying its constraint |
| `foreign("jiff::civil", "Date")` | a declaration | the module and type it maps to |
| `key(order, sku)` | an entity | the fields identifying it |
| `derive("schemars::JsonSchema")` | a declaration or the target block, repeatable | adds a derive |
| `attribute("repr(u8)")` | a declaration, field, or variant, repeatable | writes `#[repr(u8)]` |
| `boxed` | a field | writes the field's type in a `Box` |

A directive the backend does not declare is a compiler warning and is passed through anyway.

## Names

| Name | Spelling | Example |
| --- | --- | --- |
| Type, variant, trait | last segment, first letter upper-cased | `LineItem`, `Card` |
| Field, getter | `emit.Snake` | `createdAt` is `created_at` |
| Type parameter | first letter upper-cased | `T`, `From` |
| Field type | the struct, then the field in Pascal case | `LineItemQuantity` |

A type keeps its spelling beyond the first letter, so `HTTPServer` stays `HTTPServer` and a consumer can find it from the model; the header allows the lints that would rather it were `HttpServer`.
A field is the exception, because rustc's `non_snake_case` is the lint consumers notice most, and serde writes the model's spelling back.

A field spelled like a Rust keyword is a raw identifier, so `type` is `r#type` and needs no rename on the wire.
`self`, `Self`, `super`, and `crate` cannot be raw, so they get `_` appended.
The strict and reserved keywords of edition 2024, `gen` included, are escaped.

Some collisions Rust refuses, and each warns and skips its declaration, which `name` resolves:

- two fields with one snake-case spelling, as `userID` and `user_id`;
- a generated field type, key struct, or oneOf enum named like a declaration, or like another generated type;
- a declaration named `Measure` in a model with units, or `Tdl`.

A field named like a generated method, `key`, `get`, `new`, `check`, or `into_inner`, does not collide, since a Rust field and method live in separate namespaces.

## Deprecation and documentation

A doc comment becomes `///` on the type, field, or variant.
A deprecated declaration, field, or variant gets `#[deprecated(note = "reason")]`, so rustc warns at each use outside the generated impls.

## Diagnostics

These warn with the node's position, and the declaration reaching one is skipped: an extern with no mapping, a higher-kinded parameter, a set element or map key holding a float, a variant field named like the discriminant under `serde`, and a name collision Rust refuses.
`emit.Cascade` then skips every declaration naming a skipped one.

These warn and the declaration is still emitted: a unit until phase 6, a `matches` pattern RE2 refuses, a `where` constraint the backend gives no meaning to, a oneOf argument another constraint excludes, a default that fails its field's check, a default on a foreign type, a class keeping one of two dependencies, a `key` it cannot generate, and a `foreign` naming a crate the manifest lacks.

An error stops the run, and only a crate name Cargo refuses earns one.

## Checking the output

The tests run `cargo clippy --offline -- -D warnings` over every response, in a throwaway workspace whose lock file is committed, when `cargo` is on `PATH` and the crates the lock names are in the local registry.
Warnings fail the check, since generated code that compiles with warnings is noise in a consumer's build.
`checks.gen-rust` always does, over `testdata/gen/smoke`, with `rustPlatform.importCargoLock` vendoring the crates from that lock, so the build fetches nothing in the sandbox.

The backend runs no formatter, but its fixed layout is the one `rustfmt` writes, and `checks.gen-rust` runs `cargo fmt --check` so the two stay in step.

## Reverse

No reverse backend is planned in Go, since reading Rust takes a Rust parser.
[reverse.md](reverse.md) lets a plugin in another language import, and one written in Rust over `syn` could read this backend's output back, including the field types and trait impls that carry what a struct alone does not.

## Overlap with other targets

| Piece | Shared with | Where |
| --- | --- | --- |
| The class plan and cycle refusal | Go, C#, F#, Java | `emit.PlanInterfaces` |
| The wire convention, `kind` and tags | TypeScript, JSON Schema, OpenAPI, Go, C#, F# | `emit.Discriminant`, `emit.Tag` |
| `length` counted in code points | Every backend that validates | `emit.Length` |
| The RE2 check | Every backend that validates `matches` | `emit.Pattern` |
| Refusing a value at construction, no `validate` | Java | design only |
| Classes as traits with associated types and conditional impls | Haskell | design only |

Rust, Java, and .NET each print a `regexp/syntax` tree in their own dialect.
The walk over the tree is the same in all three and only the rules for each node differ, so whichever of the three is built first should put the walk in `backend/internal/emit` with a per-engine table, and the other two fill in a table.

## Open questions

- **Ranged integers.** A const-generic type in the `tdl` module, `Ranged<const MIN: i64, const MAX: i64>`, would carry `min` and `max` on an integer in the type rather than in a newtype's name, and two fields with the same range would share it. Floats and decimals cannot be const parameters on stable, so it would cover integers only.
- **A runtime crate.** A published `tdl` crate would hold `Entity`, `Violations`, the adapters, and `Measure`, so an entity of any generated crate satisfies any other's bound and units cross packages. It is a crate the project would version and publish, which no other backend asks for.
- **References.** A non-owned entity field could hold an `Arc<T>`, so two line items share one order, or the entity's key, so a model serializes as a graph of ids. Either changes what a field holds in every consumer, so it would be a directive.
- **Hash collections.** A `collections("hash")` directive could write `HashSet` and `HashMap` for a consumer who never serializes, trading the stable order for speed.
- **Borrowed models.** A `Cow<'a, str>` mapping would let a deserializer borrow from its input, at the cost of a lifetime on every type holding a string.
- **Pattern limits.** RE2 caps a repetition at 1000, and the `regex` crate caps a compiled program's size, so a nested counted repetition RE2 accepts could fail when its `LazyLock` first runs. The backend cannot compile a Rust pattern at generation time from Go, so whether to warn on nesting depth is open.
