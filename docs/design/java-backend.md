# The Java backend

Design document.
[java-backend-plan.md](java-backend-plan.md) orders the work.

The Java backend turns a resolved model into Java source.
It is called `java` in a target block, ships compiled into `tdl` and as `tdl-gen-java`, and is implemented in `backend/java`.

Java since 21 has the three things a TDL model needs most: records, sealed interfaces, and a `switch` the compiler checks for exhaustiveness over them.
It has no sum types beyond those, no newtypes that cost nothing, no unsigned integers, no nullable types, and no type classes, and each of those absences shapes a section below.

The type system cannot state a range, a length, or a pattern, so where [go-backend.md](go-backend.md) and [csharp-backend.md](csharp-backend.md) generate a `Validate` method a consumer must remember to call, Java refuses the value instead.
A record can be built only through its canonical constructor, which always runs, so a value that exists satisfies its model, and the type is the proof.
[Constraints](#constraints) says what that costs.

Where Java has no reason to differ from [csharp-backend.md](csharp-backend.md), the closest in shape, it does not.
[Overlap with other targets](#overlap-with-other-targets) says what it shares with C#, F#, and Go, and what a Kotlin or Scala target would share with it.

## What it emits

One file per top-level type, `shop/billing/Order.java`, under the target's `out`.
Java requires a public top-level type to live in a file of its name, so there is no `file` directive.
Each package also gets a `package-info.java`, which carries the nullness annotation under [Absence](#absence) and the model's package doc comment.

Every file starts the same way:

```java
// Code generated by tdl. DO NOT EDIT.
package shop.billing;

import java.time.Instant;
import java.util.List;
import java.util.Objects;
```

Every generated top-level type is annotated `@javax.annotation.processing.Generated("tdl")`, which tools that skip generated code read.
The examples below leave it out.

The package is the `package` directive, or else the model's package as written, so `shop.billing` is `shop.billing`.
A Java package is usually a reversed domain, so most consumers set `package("com.acme.billing")`.
A segment that is a Java keyword gets `_` appended, as the language specification recommends, so `shop.default` is `shop.default_`.
A model with no package and no `package` directive is an error, since a type in Java's unnamed package cannot be imported from a named one.

The backend writes no `pom.xml` or `build.gradle`.
The output needs Java 21, the oldest release in support with pattern matching for `switch`, and one annotations-only dependency, `org.jspecify:jspecify`, which `nullness("none")` removes.
Under `json("jackson")` it also needs `jackson-annotations`.

## The type mapping

| TDL | Java | Why |
| --- | --- | --- |
| `string` | `String` | |
| `int` | `long` | The spec puts no width on `int`, and Java's `int` is 32 bits. |
| `int32` | `int` | |
| `uint32` | `int` | The same 32 bits, read unsigned, as protobuf-java does; see below. |
| `int64` | `long` | |
| `uint64` | `long` | The same 64 bits, read unsigned. |
| `float32` | `float` | |
| `float64` | `double` | |
| `bool` | `boolean` | |
| `bytes` | `byte[]` | What every Java API and serializer takes; see [Equality](#equality). |
| `decimal` | `java.math.BigDecimal` | Exact and arbitrary precision, so `min` and `max` are checked. |
| `uuid` | `java.util.UUID` | |
| `instant` | `java.time.Instant` | A point on the timeline, which is what the spec means; `OffsetDateTime` also keeps an offset the model never names. |
| `date` | `java.time.LocalDate` | |
| `duration` | `java.time.Duration` | |

Nothing is a placeholder.

A required field of a numeric or boolean type is a Java primitive, so it cannot be null, and the type system says so without an annotation.
A primitive in a type argument or under [Absence](#absence) is boxed, `List<Long>`.

Java has no unsigned integers, and the two ways to hold one are a wider type with a range check or the same bits read unsigned.
The backend takes the second, because it needs no check and a `uint64` has no wider primitive to go to.
Generated comparisons use `Integer.compareUnsigned` and `Long.compareUnsigned`, `toString` writes the unsigned value, and so does the serializer under `json`.
A consumer doing arithmetic on one uses `Integer.toUnsignedLong` or `Long.divideUnsigned`, which is the cost; a `foreign` mapping to Guava's `UnsignedLong` is the alternative.

Collections:

| TDL | Java | Built with |
| --- | --- | --- |
| `List<T>`, `[T]` | `java.util.List<T>` | `List.copyOf` |
| `Set<T>`, `{T}` | `java.util.Set<T>` | `Set.copyOf` |
| `Map<K, V>`, `{K -> V}` | `java.util.Map<K, V>` | `Map.copyOf` |

A record's constructor copies each collection it is given, so a record cannot be changed through a list its caller kept.
The `copyOf` methods return unmodifiable collections and refuse a null element, which is what a non-optional element means.
A collection of optional elements, `[int?]`, is copied with `Collections.unmodifiableList(new ArrayList<>(...))` instead, which keeps the nulls.
`Set.copyOf` and `Map.copyOf` iterate in no fixed order, which a TDL set and map do not promise either.

Java's collections compare by content, so a record holding a list compares its elements, and nothing else is needed for the spec's value equality.

## Absence

Java has one absence in its type system, `Optional`, and one outside it, null, which annotations bring in:

| TDL | Java |
| --- | --- |
| `name: T` | `T name`, never null |
| `name: T?` | `Optional<T> name`, never null itself |
| `name: T \| null` | `@Nullable T name` |
| `name: T? \| null` | `Optional<T> name`, with a warning |
| `[T?]` | `List<@Nullable T>` |

`Optional` makes a consumer unwrap an absent value before reading it, and the compiler holds them to it.
Java's own guidance discourages `Optional` in a field, because it was designed for return values; a record component is both, since its accessor is a method, and an accessor returning `Optional` is the convention the Immutables and AutoValue libraries follow.
`OptionalLong` and its siblings are not used, because they lack `map` and `flatMap` and would make an optional `int` read differently from an optional `string`.

`T | null` must be present and may be null, which only matters on the wire, so it is a nullable reference rather than a second `Optional`.
`T? | null` cannot tell an absent value from a null one in either spelling, and warns as it does in C#.
A nested option inside a collection, `[int?]`, cannot be `List<Optional<Long>>` without every reader unwrapping twice, so it is a nullable element.

Every package is `@NullMarked`, from JSpecify, in its `package-info.java`, so every reference the backend does not annotate `@Nullable` is non-null.
NullAway, the Checker Framework, and IntelliJ check it at compile time, and Kotlin reads it as Kotlin's own nullability, so a Kotlin consumer of a Java model sees `String` and `String?` rather than platform types.
The constructor also checks it at run time with `Objects.requireNonNull`, since `javac` alone does not.
`nullness("none")`, on the target block, drops the annotations and the dependency, and keeps the run-time checks.

## Records

Entities, values, and mixins are records:

```java
/** An order, identified by its id. */
public record Order(
    UUID id,
    Instant createdAt,
    Instant updatedAt,
    List<LineItem> items,
    Optional<String> note,
    @Nullable LocalDate shipOn,
    @Deprecated String fax)
    implements Auditable {

  public Order {
    Objects.requireNonNull(id, "Order.id");
    Objects.requireNonNull(createdAt, "Order.createdAt");
    Objects.requireNonNull(updatedAt, "Order.updatedAt");
    items = List.copyOf(items);
    Objects.requireNonNull(note, "Order.note");
    Objects.requireNonNull(fax, "Order.fax");
  }
}
```

A record is final, its components are final, and its `equals`, `hashCode`, and `toString` read every component, which is what the spec means by a value.
A component keeps the model's spelling, so `createdAt` is `createdAt()`, and Jackson's default naming already writes the model's names.

A mixin is a record of its own, since a consumer may name it, and an including record carries its fields directly, as lowering copied them.

Construction is positional, `new Order(id, createdAt, ...)`, and the compiler checks every field is passed.
That breaks every caller when a field is added, which a nominal constructor would not; Java has none, and [Builders](#builders) is the remedy that keeps the compiler's check.

### Defaults

A record component has no default, so a default reaches Java two ways:

- the [builder](#builders) makes a defaulted field an optional step, holding the default until it is set;
- under `json("jackson")`, the record's creator fills a field the payload omits with its default.

A default on a foreign type warns and is dropped, since the backend cannot spell a value of it.

### Builders

`builder`, on a declaration or the target block, adds a staged builder:

```java
Order order = Order.builder()
    .id(id)
    .createdAt(now)
    .updatedAt(now)
    .items(items)
    .shipOn(null)
    .fax("")
    .note("gift")      // optional, may be skipped
    .build();
```

Each required field is a step, an interface whose one method returns the next, in the model's field order, so `build()` is reachable only once every required field is set.
Optional and defaulted fields come after, in any order, on the last step.
A plain builder, one class with a setter per field, would compile with a field missing and fail at `build()`, which is the check a staged builder moves to the compiler.

The cost is one small interface per required field, nested in the record, which is why it is opt-in.

### Equality

Records compare their components with `equals`, which is content equality for every mapped type but two.

A `byte[]` compares by reference, so a record holding `bytes` at any depth, `bytes`, `bytes?`, or `[bytes]`, writes its own `equals`, `hashCode`, and `toString` through `Arrays`, reaching into collections and `Optional` the way C#'s `TdlEquality` does.
Its constructor copies the array in and its accessor copies it out, so the record stays immutable at the cost of a copy per read.
A set element or a map key of type `bytes` is hashed by reference inside the JDK collection, which no record can reach, so it warns and the declaration is skipped, as in C#.
`bytes => foreign("com.google.protobuf", "ByteString")` maps it to an immutable type with content equality, and removes all of this.

`BigDecimal.equals` compares scale, so `1.5` and `1.50` are unequal, and so are two records holding them.
The backend keeps that, since normalizing would change the value a consumer wrote to the wire; [Open questions](#open-questions) has the alternative.

## Enums

A fieldless enum is a Java enum:

```java
public enum Status {
  Draft,
  Placed,
  /** @deprecated no longer issued */
  @Deprecated
  Provisional,
}
```

Constants keep the model's spelling rather than Java's `UPPER_SNAKE`, for the reason Go gives: a converted name is one a consumer cannot predict, and it would put a second spelling on the wire.
`name` renames one.

An enum where any variant carries fields is a sealed interface, with a nested record per variant:

```java
public sealed interface Payment {
  record Card(String last4) implements Payment {
    public Card {
      Objects.requireNonNull(last4, "Payment.Card.last4");
    }
  }

  record Cash() implements Payment {}
}
```

The variants are declared in the interface's own file, so the compiler infers `permits` and no other file can add one.
A consumer matches with `switch (payment) { case Payment.Card(var last4) -> ...; case Payment.Cash() -> ...; }`, and the compiler refuses a `switch` missing a variant with no `default` arm.
That is what the spec's sealed enums promise, and Java checks it where C# cannot.

Nesting keeps a variant's name in its enum's scope, so two enums may each have a `Cash`.
A generic enum with fields is a generic interface, and `Result.Ok<T>` is the variant.
A fieldless enum with parameters keeps its shape and drops them with a warning, since a Java enum cannot be generic, as in C# and Go.

## Newtypes and aliases

A newtype is a record holding its base:

```java
public record Email(String value) {}
```

It is a distinct type from `String`, and costs an allocation, which Java cannot avoid until value classes ship.

A newtype over a newtype holds its parent, not the parent's base:

```java
public record WorkEmail(Email value) {}
```

So a `WorkEmail` holds an `Email`, which already satisfies `Email`'s constraints, and the spec's rule that a value satisfying `WorkEmail` satisfies `Email` is a fact about the types.
`WorkEmail.of(String)` builds both at once.

An alias is expanded at each use, since Java has no type synonym.

## Constraints

A `where` constraint is checked in the constructor of the type it is written on:

```java
public record Email(String value) {
  public Email {
    Objects.requireNonNull(value, "Email.value");
    int n = value.codePointCount(0, value.length());
    if (n < 3 || n > 254) {
      throw new IllegalArgumentException("Email: length(3..254): got " + n);
    }
  }
}
```

There is no `validate` method, because there is no invalid value to call it on.
A record's canonical constructor runs on every construction, including Jackson's and a deserializer's, so the check cannot be skipped the way a C# `default(Email)` or a Go literal skips it.
A field constraint, `quantity: int where { min(1) }`, is checked in its record's constructor the same way.

This is as far into the type system as Java reaches: it cannot say `long` is at least one, but it can say an `Email` was checked, and every `Email` field anywhere in the model inherits that without checking again.
So a record holding a constrained type checks nothing for it, and a container never walks its elements.

A constructor checks every constraint before throwing, and the `IllegalArgumentException` lists each violation on its own line, so a consumer sees all of them at once:

```text
LineItem.quantity: min(1): got 0
```

A message is the type, the field, the constraint as written, and a detail, and never echoes a string's or bytes' contents, as in Go.
It cannot carry the path a container would prefix, `Order.items[1].quantity`, because the `LineItem` was built before any `Order` held it.
Jackson supplies that path itself, as the reference chain on the exception wrapping a creator's failure.

| Constraint | Checks |
| --- | --- |
| `min`, `max` | An integer, a float, or a `BigDecimal`, compared; an unsigned type compared unsigned |
| `length` | A string's code points, or the length of bytes, a list, a set, or a map; an integer means exactly that length |
| `matches` | A string, unanchored, through `java.util.regex` |
| `oneOf` | A string, integer, or bool equal to one argument, or a fieldless enum's constant named by one |
| `unique` | A list's elements, through `equals` |

A string's length counts code points, as C# counts runes, rather than `length()`, which counts UTF-16 units.
A pattern is compiled once, as a `private static final Pattern` on the record, after the backend parses it with Go's `regexp/syntax`; a pattern RE2 refuses warns rather than throwing when the class loads.
`java.util.regex` accepts every RE2 pattern with the same meaning for the constructs RE2 has, and `\d` and `\w` are ASCII in both.

A newtype checks only the constraints written on it, since its parent checked the rest, and a generic type checks its own fields and not its type arguments' values.

The cost of refusing at construction is that a consumer cannot hold an invalid value to show a user what is wrong with it.
A constrained newtype adds `static List<String> violations(String value)`, which runs the same checks without building, for that case.

## Identity

`key(id)` on an entity is a method returning the field, `public OrderId key() { return id; }`.
A key naming several fields returns a record nested in the entity, so a consumer can write `Map<LineItem.Key, LineItem>`:

```java
public record LineItem(Order order, Sku sku, long quantity) {
  public record Key(Order order, Sku sku) {}

  public Key key() {
    return new Key(order, sku);
  }
}
```

Nesting gives every entity a `Key` without colliding with a declaration named `LineItemKey`.
`key()` is not a bean getter, so Jackson does not write it.
A key field of type `bytes` warns, and so does a component named `key` or an entity holding a model declaration named `Key`; the entity is emitted without its key.

## Generics

A type parameter keeps its TDL spelling, so `Page<T>` is `record Page<T>`.
A primitive type argument is boxed, so `Page<int>` is `Page<Long>`.
`requires` is a bound, `Envelope<T> requires Auditable<T>` is `record Envelope<T extends Auditable>`, and a `requires` naming `Entity` warns and is dropped, as in C# and Go.

A higher kind and a `unit` kind have no Java spelling, so either warns at the parameter and skips its declaration.
A parameter spelled like a Java keyword, or like a type the declaration names, warns and skips its declaration, since Java has no escape for an identifier and a parameter named `Order` would capture the model's `Order`.

## Classes

The spec binds a class's fields on every type satisfying it, and the compiler checks it, so every implementation below compiles without a check of the backend's own.

A class is an interface whose methods are its fields' accessors, and a satisfying declaration implements it:

```java
public interface Auditable extends Timestamped {
  Instant createdAt();

  Instant updatedAt();
}

public record Order(UUID id, Instant createdAt, Instant updatedAt, ...) implements Auditable {}
```

A record's accessor implements the interface method, so a satisfying type writes nothing but the `implements` clause.
A class with no fields is an empty marker interface, and a fielded enum's sealed interface extends it.
An interface keeps the class's name, the Java convention.

The interface is not sealed, though conformance is nominal, because a package that imports this one may declare an instance for its own type, and a sealed interface lists every implementation in its own module.
Go's unexported marker refuses that case; Java's interface allows it, so an instance for a dependent's type generates there.

An associated type is a type parameter of the interface, bound by each implementation:

```java
public interface Paged<Cursor> {
  Optional<Cursor> next();
}

public record OrderList(List<Order> orders, Optional<OrderCursor> next)
    implements Paged<OrderCursor> {}
```

A `requires Paged<T>` that does not name the binding is `T extends Paged<?>`.

What an interface cannot express warns where it was written, and these are the rows of the class plan C# and F# share, with Java's one difference marked:

| Case | Result |
| --- | --- |
| A conditional instance | No implementation, since Java cannot implement an interface for some instantiations only |
| An instance for a prelude type or a type in a package this model imports | No implementation, since an interface is listed in the type's own declaration |
| A class of arrow kind | Skipped |
| A class requiring associated types | **A type parameter per associated type**, where C# and F# emit it without them |
| A two-parameter class with a dependency `from -> to` | A generic interface `Projection<To>` implemented by `from` |
| Any other multi-parameter class | Skipped |
| A class reaching itself through what it requires | Skipped |

`Entity` is the prelude's and is not generated, so `class Auditable requires Entity` is emitted without the super-interface and warns.

## Units

Java has no units of measure.
A unit-typed field is its base type, with a warning, and the declaration is emitted, as in C#, until phase 7 of the plan decides between that and phantom tags.

## Serialization

Without a directive, the output carries no serializer annotations.
Jackson 2.12 and later read records through their canonical constructor, and a component's name is the model's, so most of the model's wire convention already holds: names as the model spells them and a fieldless enum by its constant's name.

`json("jackson")` on the target block writes the annotations that put the rest of the convention, the one the TypeScript and JSON Schema backends write, into the types:

| Construct | Annotation |
| --- | --- |
| A component whose Java name differs from the model's | `@JsonProperty("class")` |
| A renamed fieldless enum constant | `@JsonProperty("Draft")` |
| A fielded enum | `@JsonTypeInfo(use = NAME, property = "kind")` and `@JsonSubTypes` naming each variant |
| A newtype | `@JsonValue` on its accessor and `@JsonCreator` on its constructor, so it is the bare base value |
| An optional field | `@JsonInclude(NON_ABSENT)`, so an empty `Optional` is left out rather than written as `null` |
| A `T \| null` field | `@JsonProperty(required = true)` |
| An unsigned field | `@JsonSerialize` and `@JsonDeserialize` naming a nested converter that reads and writes the unsigned value |
| A record with a defaulted field | A static `@JsonCreator` taking boxed values, which fills an omitted field with its default |

So `Payment.Card` is `{"kind": "Card", "last4": "4242"}` and an `Email` is `"a@b.c"`, matching what C#'s `json("stj")` writes and what the `jsonschema` backend's schema accepts.
`discriminant("type")`, on an enum or the target block, renames `kind`.

The annotations are `jackson-annotations`, which Jackson 2 and Jackson 3 share.
`Optional` and `java.time` need Jackson 2's `jdk8` and `jsr310` modules, and are built into Jackson 3.
`json` takes its library as an argument so another could follow; `jackson` is the only value, and any other warns.

## Foreign types and externs

`foreign(package, type)` maps a declaration or a primitive to a type another library declares, imported by its qualified name.
It has the shape it has in Go, Haskell, C#, and F#, so `uuid => foreign(...)` reads the same in every target block.
A `where` constraint, a class, or a `key` on a foreign type warns, since the backend does not know what it holds.

An extern resolves through its dependency's `java` target block: the package is that block's `package` directive or else the dependency's package.
An extern with neither a `foreign` mapping nor a `java` block warns and is skipped, and so is each declaration naming it.

## Directives

| Directive | On | Does |
| --- | --- | --- |
| `package("com.acme.billing")` | the target block | the package, and so the directory |
| `name("Account")` | a declaration, field, or variant | the identifier, without renaming the model |
| `foreign("java.time", "OffsetDateTime")` | a declaration | the package and type it maps to |
| `key(order, sku)` | an entity | the fields identifying it |
| `builder` | a declaration or the target block | a staged builder |
| `annotation("jakarta.annotation", "Nonnull")` | a declaration or the target block, repeatable | writes `@jakarta.annotation.Nonnull` |
| `nullness("none")` | the target block | drops the JSpecify annotations |
| `json("jackson")` | the target block | the annotations under [Serialization](#serialization) |
| `discriminant("type")` | an enum or the target block | the discriminator's property name under `json` |

`annotation` is C#'s `attribute`, with its shape.
A directive the backend does not declare is a compiler warning and is passed through anyway.

## Names

| Name | Spelling | Example |
| --- | --- | --- |
| Type, variant | last segment, first letter upper-cased | `LineItem`, `Card` |
| Component | as written, `_` appended to a keyword | `createdAt`, `class_` |
| Enum constant | as written | `Draft` |
| Interface | the class's name | `Auditable` |
| Package segment | as written, `_` appended to a keyword | `shop.default_` |

There is no other case conversion.
Java keywords are lower-case, so an upper-cased type never needs an escape.

Java resolves a simple name to a type in the same package before `java.lang`, so a model declaring `String` or `Record` would capture every use of the JDK's.
The backend writes a JDK type by its qualified name, `java.lang.String`, in any file whose package declares the simple name, and imports it otherwise.

Some collisions Java refuses, and each warns and skips its declaration, which `name` resolves:

- a variant named like its enum;
- two fields spelled alike once escaped, as `class` beside `class_`;
- a component named like a method every record has: `equals`, `hashCode`, `toString`, `getClass`, `notify`, `notifyAll`, `wait`, `clone`, or `finalize`.

A component named like a generated method, `key`, `builder`, `of`, or `violations`, warns and the type is emitted without that method.

## Deprecation and documentation

A doc comment becomes Javadoc on the type, component, constant, or variant, with `<`, `>`, `&`, and `*/` escaped.
A deprecated declaration, variant, or field gets `@Deprecated` and a `@deprecated` Javadoc tag carrying the reason, so `javac` warns at each use outside the generated file.
A record's accessors and constructor are generated from its components, so a deprecated component deprecates its accessor.

## Diagnostics

These warn with the node's position, and the declaration reaching one is skipped: an extern with no mapping, a type parameter Java cannot express, a set element or map key of `bytes`, and a name collision Java refuses.
`emit.Cascade` then skips every declaration naming a skipped one.

These warn and the declaration is still emitted: `T? | null`, a unit, a fieldless enum's parameters, a `where` constraint the backend gives no meaning to, a pattern RE2 refuses, a `requires` naming `Entity`, an instance the class plan refuses, a `key` it cannot generate, a default on a foreign type, and a generated method a component's name takes.

An error stops the run, and only a package Java refuses earns one.

## Checking the output

The tests compile every response with `javac --release 21 -Xlint:all -Werror` when `javac` is on `PATH`, against the JSpecify and `jackson-annotations` jars.
`checks.gen-java` always does, over `testdata/gen/smoke`, with `jdk21` from nixpkgs and the two jars fetched by hash, so the check runs in the sandbox.

The backend runs no formatter; its layout is fixed, close to google-java-format's, so a regenerated file diffs only where the model changed.

## Reverse

No reverse backend is in this plan, but Java is the one compiled target where a reverse in Go is small.
A class file records a record's components in its `Record` attribute, a sealed interface's variants in `PermittedSubclasses`, generic types in `Signature`, and JSpecify's annotations, which are retained at run time.
So a Go reader of `.class` files, with no JVM, recovers records, enums, optionality, and generics from a compiled jar, where C# needs a .NET plugin and Haskell needs GHC.
The constraints are code in a constructor and do not survive, which [reverse.md](reverse.md)'s loss codes already cover.

## Overlap with other targets

### With C# and F\#

Java shares no runtime with .NET, so it does not import `backend/internal/dotnet`.
It does share decisions with it, and two of them are not about .NET at all:

| Decision | Where it lives now | Who reads it |
| --- | --- | --- |
| The class plan: which instances an interface can carry, and the warning table | `backend/internal/dotnet` | C#, F#, Java, and Go's table differs only in its marker rows |
| The JSON wire convention: names as the model spells them, `kind`, internal tagging, a newtype as its bare value | `backend/internal/dotnet` | C#, F#, Java, TypeScript, JSON Schema, OpenAPI |

Both move to `backend/internal/emit`, the class plan as a decision over the model and the wire convention as a description each serializer printer reads.
`backend/internal/dotnet` keeps what is true of .NET: the base class library mapping, namespaces, `RegexOptions.ECMAScript`.
Java's one class-plan difference, an associated type as a type parameter, is available to C# and F# too, since both have generic interfaces; it becomes a row of the shared plan and the .NET targets may adopt it.

Two smaller rules are already written three times, in Go, C#, and Haskell: `matches` parsed with `regexp/syntax` at generation time, and `length` counting code points.
They move to `emit` with the class plan.

### With Kotlin and Scala

A Kotlin or Scala target would share the JVM with Java, the way F# shares .NET with C#, and a `backend/internal/jvm` would hold what is true of the JVM: the primitive mapping as JDK types, the package derived from a model's, `foreign` and `annotation`, and the Jackson wire convention.
Nothing else, since Kotlin has nullable types, value classes, unsigned integers, and default arguments, and Scala 3 has enums, opaque types, and given instances that express conditional instances, each of which this design works around.
Like `dotnet`, the layer is created by whichever JVM target needs it second; until then those rules live in `backend/java`.

A Kotlin consumer of Java output is served by the JSpecify annotations, which Kotlin reads as its own nullability, and an extern in a Kotlin target could resolve through a `java` block, as F# resolves through `csharp`.

## Open questions

- **Value classes.** When Project Valhalla's value classes ship, a newtype and a key record would cost no allocation and compare by value without a header. A `value` modifier is all the change would be.
- **Units.** See phase 7 of the plan.
- **Decimal scale.** A record could normalize a `BigDecimal` with `stripTrailingZeros` so `1.5` equals `1.50`, at the cost of writing a different scale to the wire than the consumer gave.
- **Builders by default.** A staged builder is the only Java construction that survives a field being added without breaking callers and still has the compiler check completeness. It costs an interface per required field, and the question is whether that is too much to generate unasked.
- **Violation types.** `IllegalArgumentException` with one line per violation is readable and carries no structure. A per-package exception holding a list would serve a form, at the cost of one more generated name to collide with.
- **Project files.** A `pom.xml` or `build.gradle.kts` directive, decided together with C#'s and F#'s project files.
- **Bean Validation.** `jakarta.validation` annotations, `@Size` and `@Pattern`, would let a framework report constraints, but they describe checks that run later, which this design moved into the type.
