# The C# backend

Design document.
[csharp-backend-plan.md](csharp-backend-plan.md) orders the work.

The C# backend turns a resolved model into C# source.
It is called `csharp` in a target block, ships compiled into `tdl` and as `tdl-gen-csharp`, and is implemented in `backend/csharp`.

C# and F# compile to one runtime and share its base class library, its serializer, its attributes, and its interfaces.
They share nothing else a backend cares about: C# has no type declaration order, no `and` groups, no modules, and no sum types.
So the two share a .NET layer, `backend/internal/dotnet`, and C# does not build on the ML core.
[Overlap with F#](#overlap-with-f) says where the line falls and what it changed in [ml-backends.md](ml-backends.md).

Where C# has no reason to differ from [go-backend.md](go-backend.md), the closest in shape, it does not.

## What it emits

One file per declaration the model owns, `Order.g.cs`, under the target's `out`, as in Go.
C# resolves names across every file of a project, so mutually recursive entities need no single file, and a diff stays local to the declaration that changed.
A `file("Model.g.cs")` directive in the target block writes every declaration into that one file instead.

The `.g.cs` suffix is the .NET convention for generated source, and it leaves `Order.cs` free for a consumer's own half of a partial type (see [Records](#records)).
Every file starts the same way:

```csharp
// <auto-generated>
// Code generated by tdl. DO NOT EDIT.
// </auto-generated>
#nullable enable
#pragma warning disable CS0612, CS0618

namespace Shop.Billing;
```

`<auto-generated>` tells Roslyn's analyzers to skip the file, and also turns the nullable context off, so `#nullable enable` follows it.
The pragma silences use of an obsolete member inside the file, since a record's generated `Equals` reads its deprecated fields; a consumer reading one still gets the warning.

The namespace is the `namespace` directive, or else the package's segments with each first letter upper-cased, so `shop.billing` is `Shop.Billing`.
A model with no package and no `namespace` directive is an error, as in Haskell.
It is file-scoped, and every type the file names outside it is written `global::`-qualified, so a model namespace called `System` shadows nothing.
The examples below drop `global::` for reading.

The backend writes no `.csproj`.
The output needs C# 12 and .NET 8, and nothing beyond the base class library; under `json("stj")` it needs .NET 9, for `JsonStringEnumMemberName`.

## The type mapping

| TDL | C# | Why |
| --- | --- | --- |
| `string` | `string` | |
| `int` | `long` | The spec puts no width on `int`, and C#'s `int` is 32 bits. |
| `int32` | `int` | |
| `uint32` | `uint` | |
| `int64` | `long` | |
| `uint64` | `ulong` | |
| `float32` | `float` | |
| `float64` | `double` | |
| `bool` | `bool` | |
| `bytes` | `byte[]` | What every .NET API and serializer takes; see [Equality](#equality). |
| `decimal` | `decimal` | Native, 28 digits, so `min` and `max` are checked. |
| `uuid` | `System.Guid` | |
| `instant` | `System.DateTimeOffset` | It keeps the offset a timestamp was written with; `DateTime` does not. |
| `date` | `System.DateOnly` | |
| `duration` | `System.TimeSpan` | |

This is F#'s mapping, type for type, and it lives in `backend/internal/dotnet` as base class library types each printer spells: `System.Int64` is `long` here and `int64` there.
Nothing is a placeholder.

Collections:

| TDL | C# |
| --- | --- |
| `List<T>`, `[T]` | `System.Collections.Immutable.IImmutableList<T>` |
| `Set<T>`, `{T}` | `System.Collections.Immutable.IImmutableSet<T>` |
| `Map<K, V>`, `{K -> V}` | `System.Collections.Immutable.IImmutableDictionary<K, V>` |

A record's properties are `init`-only, so it promises not to change once built.
`IReadOnlyList<T>` is a view of a list someone else may still mutate, which would change a record's hash while it sits in a dictionary.
The immutable interfaces keep the promise, ship with the runtime, and are read and written by `System.Text.Json` on every supported .NET; `IReadOnlySet<T>` is not read until .NET 11.

Optionality is a property's nullability and whether it is `required`:

| TDL | C# |
| --- | --- |
| `name: T` | `public required T Name { get; init; }` |
| `name: T?` | `public T? Name { get; init; }` |
| `name: T \| null` | `public required T? Name { get; init; }` |
| `name: T? \| null` | `public T? Name { get; init; }`, with a warning |

`required` means a constructing expression must set the property, and `System.Text.Json` refuses a payload that omits it.
So `T?` and `T | null` stay distinct: one may be left out, the other must be written and may be null.
C# has one null, so `T? | null` cannot tell an absent value from a null one, and warns.

A nested option, `[int?]`, is `IImmutableList<long?>`.
On a bare type parameter, `T?` means "`T` or its default", which for a value type is `T` itself, so an optional field typed by a bare parameter warns that absence is lost when the argument is a struct.

## Records

Entities, values, and mixins are sealed records with `init`-only properties:

```csharp
/// <summary>An order, identified by its id.</summary>
public sealed partial record Order
{
    public required Guid Id { get; init; }
    public required DateTimeOffset CreatedAt { get; init; }
    public required DateTimeOffset UpdatedAt { get; init; }
    public required IImmutableList<LineItem> Items { get; init; }
    public string? Note { get; init; }
    public required DateOnly? ShipOn { get; init; }

    [Obsolete]
    public required string Fax { get; init; }
}
```

A record is nominal, `new Order { Id = ..., ... }`, rather than positional, `Order(Guid Id, ...)`: a positional record breaks every caller when a field is added in the middle, and a property carries its own doc comment and attributes.

Every generated type is `partial`, so a consumer adds methods in a file of their own without touching the generated one.

A property is the field's name with its first letter upper-cased, so `createdAt` is `CreatedAt` and `httpURL` is `HttpURL`.
There is no other case conversion, for the reason Go gives: a table would produce names a consumer cannot predict.
It also means .NET's camel-case naming policy, which ASP.NET applies by default, turns every property back into the model's spelling.

A mixin is a record of its own, and an including record carries its fields directly, as lowering copied them.

### Defaults

C# can write a field's default, which none of the ML targets or Haskell can:

| TDL | C# |
| --- | --- |
| `status: OrderStatus = Pending` | `public OrderStatus Status { get; init; } = OrderStatus.Pending;` |
| `tags: {string} = []` | `public IImmutableSet<string> Tags { get; init; } = ImmutableHashSet<string>.Empty;` |
| `retries: int = 3` | `public long Retries { get; init; } = 3;` |

A field with a default is not `required`, and the serializer keeps the default when the payload omits it.
A default on a newtype field is wrapped in its constructor, and one on a foreign type warns and is dropped, leaving the field `required`.

### Equality

The spec says two values with equal fields are the same value.
A record compares its properties with `EqualityComparer<T>.Default`, which for an immutable collection or a `byte[]` compares references, so two orders holding equal item lists would be unequal.
A record holding a collection or bytes therefore writes its own `Equals` and `GetHashCode`, comparing those by content at any depth through an internal `TdlEquality` class each namespace declares once.
A record holding neither keeps the compiler's.

A set element or a map key whose type is `bytes` or a collection is hashed by reference inside the .NET collection itself, which no record can reach, so it warns and the declaration is skipped, as Go skips a key it cannot compare.

## Enums

A fieldless enum is a C# enum:

```csharp
public enum Status
{
    Draft,
    Placed,
    [Obsolete("no longer issued")]
    Provisional,
}
```

An enum where any variant carries fields is an abstract record closed by a private constructor, with a sealed nested record per variant:

```csharp
public abstract partial record Payment
{
    private Payment() { }

    public sealed partial record Card : Payment
    {
        public required string Last4 { get; init; }
    }

    public sealed partial record Cash : Payment;
}
```

Only a nested type can call the private constructor, so no other assembly adds a variant, and a consumer matches with `payment switch { Payment.Card c => ..., Payment.Cash => ... }`.
The compiler does not know the hierarchy is closed and asks for a discard arm; that is C#'s limit, not the model's.
Nesting keeps a variant's name in its enum's scope, so two enums may each have a `Cash`, and no prefix is needed.

A generic enum with fields is a generic record, and `Result<T>.Ok` is the variant.
A fieldless enum with parameters keeps its shape and drops them with a warning, since a C# enum cannot be generic, as in Go.

## Newtypes and aliases

A newtype is a readonly record struct holding its base:

```csharp
public readonly partial record struct Email(string Value);
```

It costs no allocation, compares by value, and is a distinct type from `string`.
`default(Email)` holds a null `Value`, which the nullable annotations cannot prevent; a constrained newtype's `Create` is the checked way to build one.
A newtype over a bare type parameter, `Wrapper<T>(T Value)`, is legal C#, where Go refuses it.

An alias is expanded at each use.
C# 12's `using` alias names any type but is per file and takes no parameters, so it cannot stand for the model's name.

## Identity

`key(id)` on an entity is a method returning the field, `public OrderId Key() => Id;`.
A key naming several fields returns a readonly record struct declared beside the entity, so a consumer can write `Dictionary<LineItemKey, LineItem>`:

```csharp
public readonly partial record struct LineItemKey(Order Order, Sku Sku);

public sealed partial record LineItem
{
    public LineItemKey Key() => new(Order, Sku);
}
```

`Key` is a method rather than a property because `System.Text.Json` writes every public property, read-only ones included, and a key property would add a `key` to the wire.
A key field whose type is a collection or bytes warns, and so does a key record colliding with a declaration of the same name; the entity is emitted without its key.

## Generics

A type parameter keeps its TDL spelling, so `Page<T>` is `record Page<T>`.
`requires` is a constraint, which C# states directly: `Envelope<T> requires Auditable<T>` is `record Envelope<T> where T : IAuditable`.
A `requires` naming `Entity` warns and is dropped, as in Go.

A higher kind and a `unit` kind have no C# spelling, so either warns at the parameter and skips its declaration.
A parameter spelled like a C# keyword is written with `@`, as `@event`.

## Classes

The spec binds a class's fields on every type satisfying it, and the compiler checks it, so every implementation below compiles without a check of the backend's own.

A class is an interface whose members are its fields' getters, and a satisfying declaration lists it:

```csharp
public partial interface IAuditable : ITimestamped
{
    DateTimeOffset CreatedAt { get; }
    DateTimeOffset UpdatedAt { get; }
}

public sealed partial record Order : IAuditable
{
    public required DateTimeOffset CreatedAt { get; init; }
    public required DateTimeOffset UpdatedAt { get; init; }
}
```

A record's auto-property implements the getter implicitly, so a satisfying type writes nothing but the base list.
A class with no fields, such as the spec's `Archived`, is an empty marker interface.
An interface is named `I` and the class's name, the .NET convention; `name` overrides it.
A fielded enum lists the interface on its abstract record, and a newtype on its struct.

What an interface cannot express warns where it was written, and these are F#'s rows, decided once in `backend/internal/dotnet`:

| Case | Result |
| --- | --- |
| A conditional instance | No implementation, since .NET cannot implement an interface for some instantiations only |
| An instance for a prelude type or a type in another package | No implementation, since an interface is listed in the type's own declaration |
| A class of arrow kind | Skipped |
| A class requiring associated types | Emitted without them |
| A two-parameter class with a dependency `from -> to` | A generic interface `IProjection<TTo>` implemented by `from` |
| Any other multi-parameter class | Skipped |
| A class reaching itself through what it requires | Skipped |

`Entity` is the prelude's and is not generated, so `class Auditable requires Entity` is emitted without the base interface and warns, as in Go.

## Validation

`where` constraints are methods on the type they check:

```csharp
public readonly partial record struct Email(string Value)
{
    public IReadOnlyList<string> Validate() => ValidateAt("Email");

    public IReadOnlyList<string> ValidateAt(string path) { ... }

    public static Email Create(string value) { ... }

    public static bool TryCreate(string value, out Email email, out IReadOnlyList<string> errors) { ... }
}
```

`Validate` returns every violation, empty when the value is valid, and `ValidateAt` threads the path a container prefixes.
A constrained newtype adds `Create`, which throws an `ArgumentException` listing the violations, and `TryCreate`, which does not.
The positional constructor stays public, as Haskell's does, because the serializer and pattern matching need it.

A message is the path, the constraint as written, and a detail, `Order.items[1].quantity: max(100): got 200`, and never echoes a string's or bytes' contents.
The path uses the model's spelling, not the property's, so it reads the same in every backend.

| Constraint | Checks |
| --- | --- |
| `min`, `max` | An integer, a float, or a `decimal`, compared |
| `length` | A string's characters, or the length of bytes, a list, a set, or a map; an integer means exactly that length |
| `matches` | A string, unanchored, through `Regex` |
| `oneOf` | A string, integer, or bool equal to one argument, or a fieldless enum's variant named by one |
| `unique` | A list's elements, through the record equality above |

A string's length counts characters by `EnumerateRunes`, as F# does, rather than `Length`, which counts UTF-16 code units.
`matches` compiles once per namespace with `RegexOptions.ECMAScript`, which makes `\d` and `\w` ASCII as RE2 does, after the backend parses the pattern with Go's `regexp/syntax`, so a pattern RE2 refuses warns rather than throwing when the type loads.
Both are F#'s rules, and live in `backend/internal/dotnet`.

A type validates the values it holds at any depth, a newtype checks the set the compiler accumulated down its chain, and a generic type does not check its type arguments' values, all as in Go.
A record with nothing to check gets none of the methods.

## Units

C# has no units of measure.
A unit-typed field is its base type, with a warning, and the declaration is emitted, as in OCaml.
F# erases its units from compiled metadata, so a C# consumer of an F# `decimal<kg>` sees `decimal` too.

## Serialization

Without a directive, the output carries no serializer attributes, and `System.Text.Json` reads it with the consumer's options: property names through their naming policy, a fieldless enum as a number, and a fielded enum not at all, since it has no discriminator.

`json("stj")` on the target block writes the attributes that put the model's wire convention, the one the TypeScript and JSON Schema backends write, into the types themselves:

| Construct | Attribute |
| --- | --- |
| A property whose C# name differs from the model's | `[JsonPropertyName("createdAt")]` |
| A fieldless enum | `[JsonConverter(typeof(JsonStringEnumConverter<Status>))]`, and `[JsonStringEnumMemberName]` on a renamed variant |
| A fielded enum | `[JsonPolymorphic(TypeDiscriminatorPropertyName = "kind")]` and a `[JsonDerivedType(typeof(Payment.Card), "Card")]` per variant |
| A newtype | `[JsonConverter]` naming a nested converter that writes the bare base value |

So `Payment.Card` is `{"kind": "Card", "last4": "4242"}` and an `Email` is `"a@b.c"`, matching what the `jsonschema` backend's schema for the same model accepts.
`discriminant("type")`, on an enum or the target block, renames `kind`, as in TypeScript and JSON Schema.
`System.Text.Json` reads a discriminator only as an object's first property unless the consumer sets `AllowOutOfOrderMetadataProperties`, which is theirs to choose.

`json` takes its library as an argument so another could follow; `stj` is the only value, and any other warns.

## Foreign types and externs

`foreign(namespace, type)` maps a declaration or a primitive to a type another assembly declares, written `global::Namespace.Type`.
It is F#'s directive, with F#'s shape, and `instant => foreign("NodaTime", "Instant")` means the same thing in both targets.
A `where` constraint, a class, or a `key` on a foreign type warns, since the backend does not know what it holds.

An extern resolves through its dependency's `csharp` target block: the namespace is that block's `namespace` directive or the dependency's package, upper-cased the same way.
An extern with neither a `foreign` mapping nor a `csharp` block warns and is skipped, and so is each declaration naming it.

## Directives

| Directive | On | Does |
| --- | --- | --- |
| `namespace("Acme.Billing")` | the target block | the namespace |
| `file("Model.g.cs")` | the target block | writes every declaration into one file |
| `name("Account")` | a declaration, field, or variant | the identifier, without renaming the model |
| `foreign("NodaTime", "Instant")` | a declaration | the namespace and type it maps to |
| `key(order, sku)` | an entity | the fields identifying it |
| `attribute("System.Runtime.Serialization", "DataContract")` | a declaration or the target block, repeatable | writes `[global::System.Runtime.Serialization.DataContract]` |
| `json("stj")` | the target block | the serializer attributes under [Serialization](#serialization) |
| `discriminant("type")` | an enum or the target block | the discriminator's property name under `json` |

`attribute` is F#'s, with F#'s shape.
A directive the backend does not declare is a compiler warning and is passed through anyway.

## Names

| Name | Spelling | Example |
| --- | --- | --- |
| Type, variant | last segment, first letter upper-cased | `LineItem`, `Card` |
| Property | first letter upper-cased | `createdAt` is `CreatedAt` |
| Interface | `I` and the class's name | `IAuditable` |
| Type parameter | as written, with `@` before a keyword | `T`, `@event` |

Every C# keyword is lower-case, so an upper-cased name never needs `@`, and only a type parameter can.

Some collisions C# refuses, and each warns and skips its declaration, which `name` resolves:

- a property or variant named like its enclosing type, as `type Tag { tag: string }`;
- two fields spelled alike once upper-cased, as `id` and `Id`;
- a property or variant named like a member every record has: `Equals`, `GetHashCode`, `ToString`, `GetType`, `Deconstruct`, `EqualityContract`, `PrintMembers`, `MemberwiseClone`, or `Finalize`;
- a declaration named `TdlEquality`, or `I` and a class's name when that class is generated.

A property named like a generated method, `Validate`, `ValidateAt`, `Create`, `TryCreate`, or `Key`, warns and the type is emitted without that method, as Go does with `Validate`.

## Deprecation and documentation

A doc comment becomes `/// <summary>...</summary>` on the type, property, or variant, with `<`, `>`, and `&` escaped.
A deprecated declaration, variant, or field gets `[Obsolete("reason")]`, so the compiler warns at each use outside the generated file.

## Diagnostics

These warn with the node's position, and the declaration reaching one is skipped: an extern with no mapping, a type parameter C# cannot express, a set element or map key hashed by reference, and a name collision C# refuses.
`emit.Cascade` then skips every declaration naming a skipped one.

These warn and the declaration is still emitted: `T? | null`, an optional bare type parameter, a unit, a fieldless enum's parameters, a `where` constraint the backend gives no meaning to, a `requires` naming `Entity`, an instance the class table refuses, a `key` it cannot generate, a default on a foreign type, and a generated method a property's name takes.

An error stops the run, and only a namespace C# refuses earns one.

## Checking the output

The tests build every response with `dotnet build` over a throwaway project with `Nullable` enabled and `TreatWarningsAsErrors` set, when `dotnet` is on `PATH`.
`checks.gen-csharp` always does, over `testdata/gen/smoke`, with the same `dotnet-sdk` from nixpkgs that `checks.gen-fsharp` uses.
The project references nothing but the framework, so the build restores nothing from NuGet and runs in the sandbox.

The backend runs no formatter; its layout is fixed, so a regenerated file diffs only where the model changed.

## Reverse

No reverse backend is planned in Go, since reading C# takes Roslyn.
[reverse.md](reverse.md) lets a plugin in another language import; a .NET plugin reading compiled assemblies through `System.Reflection.Metadata` would read C# and F# alike, which is the open question below.

## Overlap with F\#

Yes, there is overlap, and all of it is below the language.
The two targets would share the runtime's types, its attributes, its interfaces, and its regular expressions; they would share nothing about how a declaration is spelled.

### Shared, in `backend/internal/dotnet`

| Piece | Why both need it |
| --- | --- |
| The primitive mapping, as base class library types | Identical in both; only the spelling differs |
| The namespace derived from a package | `shop.billing` is `Shop.Billing` in both |
| `foreign(namespace, type)` and its validation | One directive, one shape, one meaning |
| `attribute(namespace, name)` | One directive, one shape |
| The class plan: which instances an interface can carry, and the warning table | Both map a class to an interface, under the same runtime rules |
| `matches`: the RE2 pre-check and `RegexOptions.ECMAScript` | One engine, one rule for what passes |
| `length` by runes | One string type |
| The wire convention under `json`: names as the model spells them, `kind`, internal tagging | So a C# service and an F# client agree on bytes |
| Suppressing obsolete use inside a generated file | `CS0612` and `CS0618` here, `FS0044` there, for the same reason |

`backend/internal/dotnet` holds decisions, not syntax, the way `backend/internal/emit` does; each printer stays in its own backend.
Whichever of `csharp` and `fsharp` is built first creates it, and the other imports it.

### Not shared

| Piece | C# | F# |
| --- | --- | --- |
| Core | none | `backend/internal/ml` |
| Files | one per declaration | one per model, in dependency order |
| Order | source order, none needed | `namespace rec` |
| Records | `sealed record` with `required init` properties | F# records |
| Field names | first letter upper-cased | as written |
| Enums with fields | abstract record, nested variants | discriminated union |
| Collections | `IImmutableList`, `IImmutableSet`, `IImmutableDictionary` | `list`, `Set`, `Map` |
| Absence | `T?` and `required` | `option` |
| Equality | generated where a collection is held | structural, free |
| Units | dropped, with a warning | units of measure |
| Defaults | property initializers | not read |
| Validation | methods on the type | companion module |
| Namespace directive | `namespace` | `module`, shared with its ML siblings |

### What this changed in ml-backends.md

1. **F# builds on `backend/internal/dotnet`** for the pieces above, beside `backend/internal/ml`.
2. **F# writes `requires` on a type** as `type Envelope<'T when 'T :> Auditable>`, where it had warned.
3. **F# reads `json("stj")` and `discriminant`.** FSharp.SystemTextJson's default union encoding is an adjacent `Case` and `Fields` pair, so an F# and a C# service generated from one model would have disagreed on every fielded enum. F# now writes the converter with `InternalTag`, `NamedFields`, and `UnionTagName = "kind"`, and the two profiles have one body.
4. **F# resolves an extern through a `csharp` block** when the dependency has no `fsharp` one. F# consumes C# records and interfaces directly; the reverse needs `FSharp.Core` and reads unions through generated `Is` and `New` members, so `csharp` never reads an `fsharp` block.
5. **The floor is .NET 8 with F# 8,** up from .NET 6, which is out of support, so both checks share one SDK.
6. **F# writes `#nowarn "44"`** in the generated file, since a companion module's validation reads a deprecated field.

## Open questions

- **Several targets per profile.** `profile nodatime for csharp, fsharp` maps `instant`, `date`, and `duration` to NodaTime in both, and with the shared `json` so would `stj`. It is ml-backends.md's open question for `ocaml` and `reason`, with a second reason.
- **Project files and NuGet.** A `.csproj` and a `.fsproj` are one concern: a directive naming a package id and version would make a model a NuGet package, and Nix's `buildDotnetModule` would build it. Deferred in both, as in ml-backends-plan.md.
- **Instances across packages.** Two packages generated into one assembly could carry an instance for another package's type as a `partial` declaration in that type's namespace. The backend cannot know two outputs share an assembly, so it warns today.
- **Entity equality.** A record compares every field, which is a value's equality; an entity with a `key` could compare its key alone, which is what identity means, at the cost of surprising anyone comparing two versions of one order.
- **Values as structs.** A `struct` directive could make a small value a `readonly record struct`, which saves an allocation and makes `default` a valid, empty value.
- **DataAnnotations.** Implementing `IValidatableObject` would let ASP.NET call `Validate` during model binding. The attributes, `[Range]` and `[StringLength]`, count UTF-16 code units and carry no path, so they cannot replace the methods.
- **Source generation.** Under `json("stj")`, a `JsonSerializerContext` naming every type would make the model trimmable and AOT-safe. A Roslyn incremental generator reading `.tdl` files would remove the checked-in output entirely, at the cost of the hermetic Nix workflow.
- **Reverse from assemblies.** A .NET plugin reading metadata would import C# and F# models alike, and F#'s unions and units survive in its custom attributes.
