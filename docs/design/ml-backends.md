# The ML backends

Design document.
[ml-backends-plan.md](ml-backends-plan.md) orders the work.

Four backends turn a resolved model into a language of the ML family: `ocaml`, `reason`, `fsharp`, and `sml` (Standard ML).
Each is its own target, ships compiled into `tdl` and as `tdl-gen-<name>`, and is implemented in `backend/<name>` on a shared core, `backend/internal/ml`.
The core is to these four what `backend/internal/jsonschema` is to `jsonschema` and `openapi`: one builder, and a `Dialect` stating what differs.

Where a target has no reason to differ from [haskell-backend.md](haskell-backend.md), the nearest relative, it does not.

## One core, four targets

The four languages share far more than syntax.
Each has records, sum types whose constructors carry data, type parameters written `'a`, strict evaluation, and type declarations that must be ordered or grouped with `and` to refer to one another.
None has type classes, and none expresses a higher-kinded type parameter on a type declaration.
OCaml and Standard ML share a module system, and Reason is a second syntax for OCaml that compiles to the same modules.

So most decisions are made once:

| Decided in the core | Decided per dialect |
| --- | --- |
| which declarations are emitted, warned about, or skipped, and the cascade | the type mapping |
| the order of declarations and their recursive groups | the keyword list and how a name is escaped |
| how optional, nullable, and both together are spelled | how a name is cased |
| what a newtype, an alias, a key, and a foreign type become | the class mapping: modules, or interfaces |
| the class plan: signatures, instance modules, and functors | units: native, or dropped |
| what each constraint checks, and the path in its messages | the file layout and its header |
| extern resolution | the printer |

The core builds a small ML syntax tree: type groups, records, variants, abbreviations, signatures, modules, functors, and the handful of expressions validation needs.
Each dialect prints it.
Nothing in the core knows whether a record is written `{ id : string; }`, `{id: string}`, or `{ id: string }`.

### Why not one `ml` target

A single target with a `dialect("fsharp")` directive would let a [profile](profiles.md) pick the language, `profile fsharp for ml { dialect("fsharp") }`.
It works mechanically and is wrong in four places:

- **Directives.** A backend declares its directives' shapes in the handshake, once per target. One target would accept `derive("yojson")` in an F# block, where it means nothing, without a diagnostic.
- **Externs.** A dependency's module is found through its target block of the same name. An `ml` block does not say which language the dependency was generated in without reading a directive the extern resolution would then have to trust.
- **Profiles.** A profile is `for` one target. `std.ml.yojson` would apply to an F# block, and every block would need a profile, or a `dialect` directive, before it generated anything.
- **Branching.** [profiles.md](profiles.md) says a backend never branches on a profile's name, and a dialect is exactly that branch: the profile would change the printer, the type mapping, and the keyword set, none of which is a directive.

### Why not four unrelated backends

The order of declarations, the recursive groups, the signature and functor plan for classes, and the validation plan are each as large as a printer, and each would be written four times.
Two of the four, OCaml and Reason, would be written twice for one compiler.
Every fix to one, such as a recursive group split wrongly, would need finding in the other three.

### Where profiles fit

A profile is the conventions of one ecosystem within one language, not a language.
Each target ships its own under `prelude/std/<target>.tdl`, and each sets directives its backend already reads:

```tdl
package std.ocaml

/// JSON through ppx_yojson_conv.
profile yojson for ocaml {
  derive("yojson")
}

/// Time through ptime instead of the standard library's placeholders.
profile ptime for ocaml {
  instant  => foreign("Ptime", "t")
  date     => foreign("Ptime", "date")
  duration => foreign("Ptime.Span", "t")
}
```

```tdl
package std.fsharp

/// JSON through FSharp.SystemTextJson.
profile stj for fsharp {
  attribute("System.Text.Json.Serialization", "JsonFSharpConverter")
}
```

The cost of four targets is that a convention true of both OCaml and Reason, such as `ptime`, is two profiles with one body.
The profiles are small, and [Open questions](#open-questions) names the alternative.

## What each target emits

One file per model, under the target's `out`:

| Target | File | Holds | Header |
| --- | --- | --- | --- |
| `ocaml` | `shop_billing.ml` | module `Shop_billing` | `(* Code generated by tdl. DO NOT EDIT. *)` |
| `reason` | `ShopBilling.re` | module `ShopBilling` | `/* Code generated by tdl. DO NOT EDIT. */` |
| `fsharp` | `Shop/Billing.fs` | `namespace rec Shop.Billing` | `// Code generated by tdl. DO NOT EDIT.` |
| `sml` | `shop_billing.sml` | `structure ShopBilling` | `(* Code generated by tdl. DO NOT EDIT. *)` |

The name is the `module` directive, or else the package's segments joined by the dialect's convention.
A model with no package and no `module` directive is an error, as in Haskell.

A model is one file because entities may be mutually recursive and none of these languages lets two files refer to each other.
The backends write no `dune`, `.fsproj`, `.mlb`, or `.cm` file; the consumer's build lists the module, and in F# and Standard ML a dependency's file is listed before its importer's.

The output needs OCaml 4.14, .NET 6 with F# 6, or an SML '97 implementation with the optional `Int64`, `Word64`, and `Real32` structures, which MLton, Poly/ML, and SML/NJ all provide; a model holding a set or map also needs the SML/NJ library, which rules out Poly/ML.
Reason output needs Reason 3.8.

## Order and recursion

Declarations in OCaml, Reason, and Standard ML are visible only after they are declared, unless they share a group joined by `and`.
The core computes the strongly connected components of the "names" relation over the model's own declarations, through fields, variant fields, newtype bases, and alias targets, and writes one group per component in dependency order.
Among declarations that do not depend on each other, source order is kept, so adding a declaration moves nothing else.

An alias inside a recursive group is expanded at its uses in that group, since an abbreviation cannot close a cycle.
Validation functions follow the same groups, as `let rec ... and ...`.

F# could take the same groups, but its validation functions live in companion modules, and two modules cannot be joined with `and`.
So F# writes `namespace rec` and the source order, and the core's groups go unused.

## The type mapping

| TDL | OCaml, Reason | F# | Standard ML |
| --- | --- | --- | --- |
| `string` | `string` | `string` | `string` |
| `int` | `int` | `int64` | `Int64.int` |
| `int32` | `int32` | `int32` | `Int32.int` |
| `uint32` | `int` | `uint32` | `Word32.word` |
| `int64` | `int64` | `int64` | `Int64.int` |
| `uint64` | warn | `uint64` | `Word64.word` |
| `float32` | `float` | `float32` | `Real32.real` |
| `float64` | `float` | `float` | `real` |
| `bool` | `bool` | `bool` | `bool` |
| `bytes` | `string` | `byte[]` | `Word8Vector.vector` |
| `decimal` | `string` | `decimal` | `string` |
| `uuid` | `string` | `System.Guid` | `string` |
| `instant` | `float` | `System.DateTimeOffset` | `Time.time` |
| `date` | `string` | `System.DateOnly` | `Date.date` |
| `duration` | `float` | `System.TimeSpan` | `Time.time` |

- **OCaml.** `int` is 63 bits on every 64-bit platform, so `int` and `uint32` fit without boxing, where `int64` is boxed and needs its own literals. OCaml has no unsigned type, so `uint64` warns until `foreign` maps it, as to `stdint`'s `Uint64.t`. A string is an immutable byte sequence and `bytes` a mutable buffer, so `bytes` is `string`. The standard library has no time, decimal, or UUID type: `instant` and `duration` are seconds as `float`, what `Unix.gettimeofday` returns, and `date`, `decimal`, and `uuid` are strings. The `ptime` profile maps the three time types.
- **F#.** .NET has every type the prelude names, so nothing is a placeholder. `int` is `int64` for the reason the Go backend gives: the spec puts no width on it, and F#'s `int` is 32 bits.
- **Standard ML.** `Int.int` is 32 bits under MLton, so `int` is `Int64.int`. The Basis Library has `Time` and `Date`; it has no decimal or UUID.

`decimal` is a placeholder string in OCaml and Standard ML, so `min` and `max` on one warn, as in Go.

Collections:

| TDL | OCaml | Reason | F# | Standard ML |
| --- | --- | --- | --- | --- |
| `List<T>`, `[T]` | `t list` | `list(t)` | `T list` | `t list` |
| `Set<T>`, `{T}` | `T_set.t` | `TSet.t` | `Set<T>` | `TSet.set` |
| `Map<K, V>`, `{K -> V}` | `v K_map.t` | `KMap.t(v)` | `Map<K, V>` | `v KMap.map` |
| `Option<T>`, `T?` | `t option` | `option(t)` | `T option` | `t option` |
| `Nullable<T>`, `T \| null` | `t option` | `option(t)` | `T option` | `t option` |

F#'s `Set` and `Map` are built in and need only `comparison`, which every generated record and union has.

OCaml's `Set` and `Map` are functors rather than parameterized types, so a set is a module applied once per element type, and a map once per key type:

```ocaml
module Sku_set = Set.Make (struct type t = sku let compare = compare_sku end)
module Status_map = Map.Make (struct type t = status let compare = compare_status end)

type order = { skus : Sku_set.t; byStatus : int Status_map.t }
```

A primitive uses the standard library's module, as in `Set.Make (String)`.
Each module is written after the group declaring its element and before the first group holding it.

Polymorphic `compare` looks at a balanced tree's shape rather than its elements, so two equal sets can compare unequal, and a set of records holding sets would hold duplicates.
The backend therefore writes `compare_<name>` for every declaration used as an element or key, field by field, calling a set's or map's own `compare` for a field holding one and polymorphic `compare` elsewhere.
It writes `equal_<name>` for every declaration holding a set or map at any depth, since `=` on one has the same flaw; [Directives](#directives) says what this changes for a consumer.

An element in its holder's own recursive group, such as an `order` holding a set of `order`, cannot have its module declared first.
That group becomes recursive modules, which is the OCaml manual's own example of them:

```ocaml
module rec Order : sig
  type t = { id : string; related : Order_set.t }
  val compare : t -> t -> int
end = struct
  type t = { id : string; related : Order_set.t }
  let compare a b = ...
end

and Order_set : Set.S with type elt = Order.t = Set.Make (Order)
```

Only that group changes: its types are spelled `Order.t` everywhere, including in instance modules and validation, and every other declaration stays a plain type.

A set or map whose element or key names a type parameter, as a `Page<T>` holding `{T}` does, has no single type to apply the functor to.
It warns and skips its declaration; [Open questions](#open-questions) has the alternative.

Standard ML's Basis has no set or map.
The `sml` target uses the `ORD_SET` and `ORD_MAP` functors from the SML/NJ library, `RedBlackSetFn` and `RedBlackMapFn`, which ship with SML/NJ and MLton and are a dependency the output names only when the model holds a set or map.
Standard ML has no polymorphic comparison, so `compare` is generated for every element and key type, and has no recursive modules, so an element in its holder's recursive group warns and skips the group.

`T? | null` is `t option option`, as in Haskell.

## Records

Entities, values, and mixins are records.
A mixin is a record of its own, and an including record carries its fields directly.

```ocaml
(** An order, identified by its id. *)
type order = {
  id : string;
  createdAt : float;
  updatedAt : float;
  items : line_item list;
  note : string option;
  shipOn : string option;
  fax : string [@deprecated];
}
```

Fields keep the model's spelling, with the first letter lower-cased where the language requires it.
Every serializer these languages have, `ppx_yojson_conv`, `ppx_deriving_yojson`, `System.Text.Json`, and Thoth, reads a field's name as its wire name, so case conversion would change the wire format of a model that never asked for it.
`name` renames one field.

OCaml, Reason, and F# disambiguate two records sharing a field name by type, and the generated code annotates every function's argument so it always can.
Standard ML records are structural, so a shared field name is no collision at all.

Standard ML writes a record as a one-constructor datatype, `datatype order = Order of {id : string, ...}`, because a record abbreviation cannot be recursive and is not a new type.

## Enums

An enum is a variant type.
A variant with fields carries an inline record, so its fields keep their names:

| | Payment |
| --- | --- |
| OCaml | `type payment = Card of { last4 : string } \| Cash` |
| Reason | `type payment = \| Card({last4: string}) \| Cash;` |
| F# | `type Payment = \| Card of last4: string \| Cash` |
| Standard ML | `datatype payment = Card of {last4 : string} \| Cash` |

OCaml, Reason, and F# resolve two enums sharing a constructor by type, and generated code qualifies or annotates every use.
Standard ML does not: a later constructor shadows an earlier one, so a constructor collision in `sml` warns at the later declaration, which is skipped.
`name` renames the variant, and `prefix`, on an enum or the target block, writes the enum's name in front of each, as in Haskell.

## Newtypes and aliases

A newtype is a one-constructor variant, which costs nothing at runtime where the language allows it:

| | Email |
| --- | --- |
| OCaml | `type email = Email of string [@@unboxed]` |
| Reason | `[@unboxed] type email = Email(string);` |
| F# | `[<Struct>] type Email = Email of string` |
| Standard ML | `datatype email = Email of string` |

The constructor is public, as in Haskell, and a `where` constraint adds a smart constructor.

An alias is a type abbreviation, `type tags = string list`, outside a recursive group, and expanded inside one.

## Identity

`key(id)` on an entity writes a function returning the field, `order_key : order -> string` in OCaml and Standard ML.
A key naming several fields returns a record, `line_item_key`, declared after the entity's group.
F# writes it as a member, `member this.Key`, with a `LineItemKey` record for several fields.
A declaration whose name the key record's would take warns, and the entity is emitted without its key.

## Generics

A type parameter is a type variable: `'t` in OCaml and Standard ML, `'T` in F#, and `'t` written `page('t)` in Reason.
`Page<T>` is `type 't page`, `type page('t)`, `type Page<'T>`, or `datatype 't page`.

None of the four takes a type constructor as a parameter of a type declaration, so a parameter of arrow kind, as in `Collection<f, T>`, warns and skips its declaration.
OCaml could spell one as a functor over a module holding `'a t`, at the cost of the declaration no longer being a type; [Open questions](#open-questions) has it.

`requires` on a type has nowhere to go in any of the four, and warns once at the clause, as in Haskell.

## Classes

The spec binds a class's fields on every type satisfying it, conditional instances included, and the compiler checks it.
So a backend never meets an instance whose type lacks a field its class requires, and every row below can be generated without a check of its own.

### As modules: OCaml, Reason, Standard ML

A class is a module type, which is the ML spelling of a type class: an abstract type for each parameter, an accessor for each field, and an abstract type for each associated type.
An instance is a module ascribing it.

```ocaml
module type Auditable = sig
  type t
  include Timestamped with type t := t
  val createdAt : t -> float
  val updatedAt : t -> float
end

module Order_auditable : Auditable with type t = order = struct
  type t = order
  let createdAt (x : t) = x.createdAt
  let updatedAt (x : t) = x.updatedAt
end
```

A conditional instance is a functor, which is exactly what it means: given an auditable `t`, a page of `t` is auditable.

```ocaml
module Page_auditable (T : Auditable) : Auditable with type t = T.t page = struct
  type t = T.t page
  let createdAt (x : t) = x.createdAt
  let updatedAt (x : t) = x.updatedAt
end
```

| TDL | OCaml |
| --- | --- |
| `class Auditable: Timestamped` | `include Timestamped with type t := t` |
| `class Projection<from, to>` | `module type Projection = sig type from type to_ end` |
| `class Projection<from, to> \| from -> to` | the same; a module is one instance, and the compiler already refused a second |
| `type Cursor` in a class | `type cursor` in the signature |
| `type Cursor = OrderCursor` in an instance | `type cursor = order_cursor` in the module |
| `class Container<f: type -> type>` | `module type Container = sig type 'a f end` |
| `instance Container<List>` | `module List_container : Container with type 'a f = 'a list` |
| `instance <T> Auditable<Page<T>> requires Auditable<T>` | a functor over `Auditable` |

A one-parameter class's type is `t`; a multi-parameter class names its types after its parameters.
An instance module is named after the type and the class, `Order_auditable`, and one for several types joins them, `Order_order_summary_projection`.
An instance for a type in another package, or a prelude type, is an ordinary module, since a module may describe any type in scope; the spec already places it in one of the two packages, so it is generated once.

Standard ML declares signatures and functors only at top level, so `sml` writes each class's signature before the model's structure, named after the structure and the class, `SHOP_BILLING_AUDITABLE`, and each functor after it.
Instance structures go inside the model's structure.

`Entity` is the prelude's and is not generated, so `class Auditable requires Entity` is emitted without the include and warns, as in Go and Haskell.

### As interfaces: F\#

F# has modules without functors or signatures to ascribe, and .NET's interfaces are its contracts.
A class is an interface whose members are its fields' getters, and a type satisfying it implements the interface in its own declaration:

```fsharp
type Auditable =
    inherit Timestamped
    abstract createdAt: System.DateTimeOffset
    abstract updatedAt: System.DateTimeOffset

type Order =
    { id: System.Guid
      createdAt: System.DateTimeOffset
      updatedAt: System.DateTimeOffset }

    interface Auditable with
        member this.createdAt = this.createdAt
        member this.updatedAt = this.updatedAt
```

What an interface cannot express warns where it was written:

| Case | Result |
| --- | --- |
| A conditional instance | No implementation, since .NET cannot implement an interface for some instantiations only |
| An instance for a prelude type or a type in another package | No implementation, since an interface is implemented in the type's own declaration |
| A class of arrow kind | Skipped |
| A class requiring associated types | Emitted without them |
| A two-parameter class with a dependency `from -> to` | A generic interface `Projection<'to>` implemented by `from` |
| Any other multi-parameter class | Skipped |

## Validation

`where` constraints generate the functions Haskell's do, named in each language's way:

| | Validate | With a path | Smart constructor |
| --- | --- | --- | --- |
| OCaml, Standard ML | `validate_email` | `validate_email_at` | `make_email : string -> (email, string list) result` |
| Reason | `validateEmail` | `validateEmailAt` | `makeEmail` |
| F# | `Email.validate` | `Email.validateAt` | `Email.create : string -> Result<Email, string list>` |

The Basis Library has no result type, so an `sml` structure needing a smart constructor declares `datatype ('a, 'e) result = Ok of 'a | Error of 'e` once.

A message is the path, the constraint as written, and a detail, as in Go and Haskell, and never echoes a string's or bytes' contents.

| Constraint | Checks |
| --- | --- |
| `min`, `max` | An integer, a float, or an F# `decimal`, compared |
| `length` | A string's characters, or the length of bytes, a list, a set, or a map; an integer means exactly that length |
| `oneOf` | A string, integer, or bool equal to one argument, or a fieldless enum's variant named by one |
| `unique` | A list's elements, with structural comparison |
| `matches` | F# only; warns in the others |

A string's length counts characters, as in Go: OCaml decodes with `String.get_utf_8_uchar`, F# counts `EnumerateRunes`, and Standard ML counts bytes that do not begin `10` through a helper the structure declares once.

F# generates `matches` with `Regex` under `RegexOptions.ECMAScript`, which makes `\d` and `\w` ASCII as RE2 does, compiled once per namespace.
The backend parses the pattern with Go's `regexp/syntax` first, so a pattern RE2 refuses warns rather than failing when the module loads.
OCaml's `Str` and every Standard ML regex library have their own dialects, so `matches` warns there and the rest of the type's constraints are generated, as in Haskell.

## Units

F# has units of measure, and they are TDL's: declared, derived, and normalized before comparison.

```fsharp
[<Measure>] type kg
[<Measure>] type m
[<Measure>] type s
[<Measure>] type N = kg m / s^2
```

`decimal<kg>` is `decimal<kg>`, and `decimal<kg*m/s^2>` is written from its reduced dimensions as `decimal<kg m / s^2>`, which F# equates with `decimal<N>` as TDL does.
F# puts units only on its numeric types, so a unit on a `string` warns and is dropped.

OCaml, Reason, and Standard ML have no units; a unit-typed field is its base type, with a warning, and the declaration is emitted.
Phantom types are the open question below.

## Foreign types and externs

`foreign(module, type)` maps a declaration or a primitive, written `Module.type` in OCaml, Reason, and Standard ML and `Namespace.Type` in F#.
It has the shape it has in Go and Haskell.

An extern resolves through its dependency's target block of the same name, as in Haskell, with one exception: `ocaml` and `reason` read each other's blocks, since both compile to one module system.
The type's spelling then comes from the block's own dialect, so an OCaml model naming a Reason dependency's `lineItem` writes `ShopOrders.lineItem`.

## Directives

| Directive | On | Targets | Does |
| --- | --- | --- | --- |
| `module("Billing")` | the target block | all | the module, namespace, or structure name, and so the file's path |
| `name("Account")` | a declaration, field, or variant | all | the identifier, without renaming the model |
| `foreign("Data.UUID", "t")` | a declaration | all | the module and type it maps to |
| `key(order, sku)` | an entity | all | the fields identifying it |
| `prefix` | an enum or the target block | all | writes variants with the enum's name in front |
| `derive("yojson")` | a declaration or the target block, repeatable | `ocaml`, `reason` | adds the name to `[@@deriving ...]` on each type in the group |
| `attribute("System.Text.Json.Serialization", "JsonFSharpConverter")` | a declaration or the target block, repeatable | `fsharp` | writes `[<JsonFSharpConverter>]`, opening the namespace |

F# derives structural equality and comparison for every record and union, and OCaml's polymorphic `=` and `compare` serve every declaration except one holding a set or map, which gets the `equal_` and `compare_` functions [the type mapping](#the-type-mapping) describes.
The names are ppx_deriving's, so a declaration carrying `derive("eq")` or `derive("ord")` gets the ppx's function instead of the backend's, and a consumer reads the same name either way.
Standard ML's datatypes admit `=` where their contents do, and its sets and maps are compared with the generated functions.

## Names

| | Type | Constructor | Field, value | Module | Escape |
| --- | --- | --- | --- | --- | --- |
| OCaml | `line_item` | `Card` | as written | `Order_auditable` | `type_` |
| Reason | `lineItem` | `Card` | as written | `OrderAuditable` | `type_` |
| F# | `LineItem` | `Card` | as written | `OrderAuditable` | ``` ``type`` ``` |
| Standard ML | `line_item` | `Card` | as written | `OrderAuditable` | `type'` |

A field keeps its spelling, with the first letter lower-cased in OCaml, Reason, and Standard ML, which require it.
Each dialect holds its keyword list from its language's manual.
F#'s double backticks keep the name exactly, so an F# field never changes its wire name; the others append a character, as Haskell does.
A type whose name collides after case conversion, or with an escape, warns and is skipped.

A model type named like a predefined one, such as a `String` beside `string`, would shadow it.
The backend then writes the predefined type through its standard module: `String.t`, `Int.t`, or `Option.t` in OCaml, `String.string` or `Int.int` in Standard ML.
F# writes every .NET type fully qualified and opens nothing.

## Deprecation and documentation

| | Doc comment | Deprecated |
| --- | --- | --- |
| OCaml | `(** ... *)` | `[@@deprecated "..."]` on a type, `[@deprecated "..."]` on a constructor or field |
| Reason | `/** ... */` | `[@deprecated "..."]` |
| F# | `/// ...` | `[<System.Obsolete("...")>]` |
| Standard ML | `(* ... *)` | the reason in the comment only |

## Diagnostics

These warn with the node's position, and the declaration reaching one is skipped: an extern with no mapping, a parameter of arrow kind on a type, a name that cannot be escaped, an `sml` constructor collision, an OCaml `uint64` with no `foreign`, a set or map over a type parameter outside F#, and an `sml` set or map whose element is in its holder's recursive group.
`emit.Cascade` then skips every declaration naming a skipped one.

These warn and the declaration is still emitted: `matches` outside F#, a constraint the backend gives no meaning to, a `requires` clause on a type, a `requires` naming `Entity`, a unit outside F# or on a non-numeric F# type, and an F# instance the table above refuses.

An error stops the run, and only a module name the language refuses earns one.

## Checking the output

Each target's tests check every response with its compiler when it is on `PATH`, with warnings as errors, and its nix check always does, over `testdata/gen/smoke`:

| Target | Check |
| --- | --- |
| `ocaml` | `ocamlc -c -warn-error +a` |
| `reason` | `refmt --print ml`, then the OCaml check |
| `fsharp` | `dotnet fsi --warnaserror+` over a script loading the file |
| `sml` | `mlton -stop tc` over a `.mlb` naming the Basis, the SML/NJ library, and the file |

The backends run no formatter.

## Reverse

No reverse backend is planned, for the reason Haskell gives: each language's parser lives in its own runtime.

## Open questions

- **Several targets per profile.** `profile ptime for ocaml, reason` would remove the duplicated profiles. It needs a profile's directive shapes checked against every target it names.
- **Higher kinds in OCaml.** A declaration with an arrow-kind parameter could be a functor over `sig type 'a t end` producing the type. It generates where today warns, and gives a consumer a module to apply instead of a type to name.
- **Phantom units.** OCaml, Reason, and Standard ML could tag a quantity with an empty type per named unit, `type kg`, as Haskell's phase 6 weighs; a unit expression has no name to tag with.
- **Sets over a type parameter.** A declaration holding `{T}` could become a functor over `T`'s ordering, `module Page (T : Set.OrderedType) = struct type t = { items : Set.Make(T).t } end`, generating where today warns, at the cost of the declaration no longer being a type a consumer names directly. The same move answers higher kinds above.
- **ReScript.** It began as Reason and now differs in its standard library, its integers, and its records. It would be a fifth dialect of the core, not a printer over `reason`.
- **Defaults and serialization.** As in Haskell: `Field.default_value` is not read, and JSON is the consumer's, through `derive` or `attribute`.
