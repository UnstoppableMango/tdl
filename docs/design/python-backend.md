# The Python backend

Design document.
[python-backend-plan.md](python-backend-plan.md) orders the work.

The Python backend turns a resolved model into a Python module.
It is called `python` in a target block, ships compiled into `tdl` and as `tdl-gen-python`, and is implemented in `backend/python`.

Python checks no annotation when it runs, so its type system is the one a static checker reads, and the output is written for `mypy --strict` and Pyright's strict mode.
That decides how a constraint is carried.
Where the checker can state a constraint, as `Literal["USD", "EUR"]` states a `oneOf`, the backend writes that type and nothing checks it at runtime, as nothing checks a field's `int` at runtime.
Where it cannot, the constraint is a nominal type whose constructor refuses a violating value, so a value the checker accepts as an `Email` was checked when it was built.
There is no `validate` method anywhere in the output, as in [rust-backend.md](rust-backend.md); [Constraints](#constraints) says how, and what it costs.

Where Python has no reason to differ from [haskell-backend.md](haskell-backend.md) and [rust-backend.md](rust-backend.md), which share its sum types and its one module per model, it does not.

## What it emits

One module per model, `shop/billing/__init__.py` for package `shop.billing`, under the target's `out`.
The module path is the `module` directive, or else the package, so a consumer imports `shop.billing`.
A model with no package and no `module` directive is an error, since a module needs a name.

The module is a package's `__init__.py` rather than `shop/billing.py`, because a model `shop` beside a model `shop.billing` would otherwise be both `shop.py` and the directory `shop/`, and Python imports the file and never finds the directory.
The directories above it get no `__init__.py`, so `shop/` is a namespace package another `out` may also contribute to.

A module is one file rather than one per declaration, because entities may be mutually recursive and two Python modules importing each other at load time is an error waiting on import order.

Every file starts the same way:

```python
# Code generated by tdl. DO NOT EDIT.
from __future__ import annotations

import dataclasses as _dataclasses
import datetime as _datetime
import typing as _t
```

`from __future__ import annotations` leaves every annotation unevaluated, so a field may name a declaration written below it, and declarations are written in source order.
A base class is evaluated when its `class` statement runs, so a declaration subclassing another, a newtype over a newtype or a protocol requiring another, is written after it, and otherwise source order holds.

Every module the output uses is imported under an alias starting with `_`, and every name from it is written through the alias, `_datetime.date` rather than `date`.
A dataclass field named `date` and annotated `date` resolves its annotation to the field itself, since `typing.get_type_hints` reads the class's namespace first, and the aliases leave a model's fields and declarations nothing to shadow.
The examples below drop the aliases for reading.

The output needs Python 3.13, for `warnings.deprecated` and the PEP 695 syntax for type parameters and aliases, and nothing outside the standard library.
The backend writes no `pyproject.toml`, since the module belongs to the consumer's distribution.

## The type mapping

| TDL | Python | Why |
| --- | --- | --- |
| `string` | `str` | |
| `int` | `int` | Python's `int` has no width, as the spec's has none. |
| `int32` | `int` | Python has no fixed-width integer; see below. |
| `uint32` | `int` | |
| `int64` | `int` | |
| `uint64` | `int` | |
| `float32` | `float` | A Python `float` is 64 bits. |
| `float64` | `float` | |
| `bool` | `bool` | |
| `bytes` | `bytes` | Immutable, unlike `bytearray`. |
| `decimal` | `decimal.Decimal` | Exact, in the standard library. |
| `uuid` | `uuid.UUID` | |
| `instant` | `datetime.datetime` | Aware; see below. |
| `date` | `datetime.date` | |
| `duration` | `datetime.timedelta` | |

A fixed width is a range, and a range is a constraint the checker cannot state, so the module declares `Int32`, `Uint32`, `Int64`, and `Uint64` once each when it uses them, as checked types under [Constraints](#constraints) whose constructors refuse a value outside the width.
A field typed `int32` is an `Int32`, and a constrained one subclasses it.
That is the one place a primitive is checked, and `width("unchecked")` on the target block writes the fixed-width integers as plain `int` for a consumer who would rather not pay for it.
`float32` holds a `float` and is not narrowed, since rounding to single precision is not a refusal.

`datetime.datetime` is aware or naive at runtime, and the checker cannot tell them apart.
An `instant` holds an aware value; a naive one is refused only where a field's type is checked, so the constructors the backend writes refuse it and a dataclass field does not.

Nothing is a placeholder, and nothing needs a dependency.

Collections:

| TDL | Python |
| --- | --- |
| `List<T>`, `[T]` | `tuple[T, ...]` |
| `Set<T>`, `{T}` | `frozenset[T]` |
| `Map<K, V>`, `{K -> V}` | `Mapping[K, V]` |

Every generated struct is frozen and hashable (see [Structs](#structs)), so what it holds must not change after it is built: a `list` would let a caller append to an order's items and change its hash while it sits in a set.
A tuple and a frozenset are immutable and hashable.
The standard library has no immutable mapping, so a map is annotated `Mapping`, which has no mutating methods for the checker to accept, and cannot be hashed.
A field whose type reaches a map other than through a generated declaration, as `{K -> V}`, `[{K -> V}]`, or `{K -> V}?` do, is left out of its struct's hash with `field(hash=False)`, which keeps equal values hashing equal.
A field holding a generated struct needs nothing, since that struct already leaves its own map fields out, so every generated type is hashable.
A set element or map key whose type reaches a map the same way warns and the declaration is skipped, since it cannot be hashed.

Absence:

| TDL | Python |
| --- | --- |
| `name: T?` | `name: T \| None = None` |
| `name: T \| null` | `name: T \| None`, with no default |
| `name: T? \| null` | `name: T \| None \| Unset = UNSET` |

A `T?` may be left out of the constructor and a `T | null` must be passed, so the two stay distinct to the checker, as they are in C#.
Python has one `None`, so `T? | null` uses a sentinel the module declares once, `class Unset(enum.Enum)` with the one member `UNSET`, which a module constant `UNSET` names, and a field that was never set is `UNSET` while one set to null is `None`.
A sentinel enum is what PEP 661 recommends until the language has sentinels, and the checker narrows it with `is`.

## Structs

Entities, values, and mixins all lower to `ir.Struct`, and each is a frozen dataclass:

```python
@dataclass(frozen=True, slots=True, kw_only=True)
class Order:
    """An order, identified by its id."""

    id: UUID
    created_at: datetime
    updated_at: datetime
    items: tuple[LineItem, ...]
    note: str | None = None
    ship_on: date | None
```

`frozen` makes the struct a value, compared and hashed by its fields, as the spec says a value is.
`kw_only` makes the constructor nominal, `Order(id=..., created_at=...)`, so adding a field in the middle of a model breaks no caller, which is why C# writes nominal records; it also lets a field with a default come before one without.
`slots` keeps a struct from growing attributes the model does not declare.

Fields are the model's names in snake case, `createdAt` as `created_at`, since PEP 8 and every linter a consumer runs ask for it.
The conversion is `emit.Snake`, and [Serialization](#serialization) writes the model's spelling back on the wire.

A mixin is a dataclass of its own, since a consumer may name it, and an including struct carries its fields directly rather than subclassing it, as lowering already copied them.

A struct's constructor checks nothing itself, so a struct is valid only as far as the checker was run on the code building it.
That is the bargain every Python type makes, and [Constraints](#constraints) puts the constraints a checker cannot state where a runtime check guards them.

### Defaults

A dataclass takes a default directly, so a field's default is written on the field:

| TDL | Python |
| --- | --- |
| `status: OrderStatus = Pending` | `status: OrderStatus = OrderStatus.PENDING` |
| `tags: {string} = []` | `tags: frozenset[str] = frozenset()` |
| `retries: int = 3` | `retries: int = 3` |
| `labels: {string -> string} = {}` | `labels: Mapping[str, str] = field(default_factory=dict[str, str])` |

A tuple and a frozenset are immutable, so one value can be shared by every instance; a map default is a factory, since a shared `dict` is the mutable default dataclasses refuse.
A default whose field type is checked is checked at generation time and written through the type's constructor, and one that fails warns and is dropped, since it could never be held.
A default on a foreign type warns and is dropped.

## Enums

A fieldless enum is a `StrEnum` whose values are the variants' tags:

```python
class Status(StrEnum):
    DRAFT = "Draft"
    PLACED = "Placed"
    PROVISIONAL = "Provisional"
    """Deprecated: no longer issued."""
```

A member is the variant in screaming snake case, `emit.ScreamingSnake`, as PEP 8 writes a constant, and its value is `emit.Tag`, the model's spelling, so `Status("Draft")` reads one off the wire.

An enum where any variant carries fields is a union of frozen dataclasses, one per variant, and a type alias naming the union:

```python
@dataclass(frozen=True, slots=True, kw_only=True)
class Card:
    last4: str

@dataclass(frozen=True, slots=True, kw_only=True)
class Cash:
    pass

type Payment = Card | Cash
```

Python has no sealed class, but a union is closed: a `match` over a `Payment` with `assert_never` in its last arm is checked for exhaustiveness by both checkers, and mypy under `exhaustive-match` checks one without it; a third variant is a checker error at every such `match`.
`case Card(last4=last4)` destructures a variant, since keyword patterns need no `__match_args__`.
A fieldless variant is an empty dataclass, and every instance of it is equal.

A `type` statement makes `Payment` a `TypeAliasType`, which `isinstance` refuses, so a consumer tests `isinstance(p, Payment.__value__)` or matches on the variants.
A generic enum is a generic alias over generic variants, `type Result[T] = Ok[T] | Err`.

Variants are classes in the module's namespace, so two enums with a `Cash` collide, as constructors do in Haskell.
A variant named like another variant or another declaration warns at the later declaration, which is skipped.
`name` renames the variant, and `prefix`, on an enum or the target block, writes every variant class as the enum's name followed by its own, as in `PaymentCash`; it is not the default because the unprefixed spelling is the one a pattern reads best.

## Newtypes and aliases

A newtype is a subclass of its base, when its base is a class Python lets a subclass extend: `str`, `int`, `float`, `bytes`, `Decimal`, `UUID`, `date`, `datetime`, `timedelta`, `tuple`, or `frozenset`.

```python
class Sku(str):
    __slots__ = ()
```

So a `Sku` is a distinct type to the checker, which refuses a plain `str` where one is expected, and is a `str` everywhere one is accepted, with no wrapper to unpack.
`isinstance` and class patterns see it, which `typing.NewType` would not.
At runtime it compares equal to the `str` it holds and to another newtype over the same string, since equality is `str`'s; the checker is what keeps two newtypes apart.

A newtype over anything else, a `bool`, a map, an optional, a union, a generated declaration, or a type parameter, is a frozen dataclass holding it:

```python
@dataclass(frozen=True, slots=True)
class Flags:
    value: Mapping[str, bool] = field(hash=False)
```

Its `value` follows the map rule under [The type mapping](#the-type-mapping), so a wrapper over a map hashes like a struct holding one.

A newtype over another newtype subclasses its parent, or holds it when the parent is a wrapper, as Rust's holds its parent, so a `WorkEmail` is an `Email` with something added and checks only what it adds.

An alias is a `type` statement, transparent as TDL's is, and keeps the model's name readable in a signature.
A parameterized alias is a parameterized one, `type Pair[K, V] = Mapping[K, V]`.

## Constraints

Every `where` constraint is either a type the checker reads, or a type the value must be built through.

### Constraints the checker states

| Constraint | Type |
| --- | --- |
| `oneOf("USD", "EUR")` on a string | `Literal["USD", "EUR"]` |
| `oneOf(1, 2, 3)` on an integer, `oneOf(true)` on a bool | `Literal[1, 2, 3]`, `Literal[True]` |
| `oneOf(Draft, Placed)` on a fieldless enum | `Literal[Status.DRAFT, Status.PLACED]` |
| `min` and `max` on an integer, spanning at most 16 values | `Literal[1, 2, 3, 4]` |
| `length(N)` on a list, for `N` at most 16 | `tuple[T, T, T]` |

A type here is what the checker refuses, so `Order(currency="GBP")` is an error before the code runs, and a `match` over a `Literal` is checked for exhaustiveness as one over an enum is.
The 16-value bound is the one the TypeScript backend's `narrow.go` uses for the same choice, and the two read one rule (see [Overlap with other targets](#overlap-with-other-targets)).
A field holding one of these is annotated with the `Literal` directly; a newtype holding one is a `type` alias, since `Literal` cannot be subclassed, and so it is not a distinct type from its base's literals.
A constraint mixed with one the checker cannot state, as `oneOf` beside `matches`, makes the whole set a checked type below, so no constraint is split between the two.

### Checked types

A constrained newtype's constructor checks every constraint before it fails:

```python
class Email(str):
    __slots__ = ()

    def __new__(cls, value: str) -> Self:
        violations = cls.check(value)
        if violations:
            raise _invalid("Email", violations)
        return super().__new__(cls, value)

    @staticmethod
    def check(value: str) -> list[str]: ...
```

`check` runs the same checks without building, for a consumer who wants to show a user what is wrong with a value they cannot hold.
A failure is a `ValueError` whose message names the type and the count, with one note per violation through `add_note`, so `except ValueError` catches it, a traceback shows every violation, and a framework that turns a `ValueError` from a validator into a field error (Pydantic does) needs no adapter.
`_invalid` is the one helper the module declares for it.
A wrapper newtype checks in `__post_init__`, which a frozen dataclass runs on every construction, `dataclasses.replace` included.

There is no unchecked constructor.
`object.__new__` and `object.__setattr__` can reach past any Python class, and the backend does not pretend otherwise; what it promises is that every way the output offers to build a value checks it.

A constraint on a field the checker cannot state is carried by a type named for the struct and the field, declared beside the struct, as in Rust:

```python
@dataclass(frozen=True, slots=True, kw_only=True)
class LineItem:
    sku: Sku
    quantity: LineItemQuantity

class LineItemQuantity(int):
    __slots__ = ()
    def __new__(cls, value: int) -> Self: ...
```

So `LineItem(sku=sku, quantity=0)` is a checker error, since `0` is an `int` and not a `LineItemQuantity`, and `LineItemQuantity(0)` raises.
A variant's field is `<Enum><Variant><Field>`, `PaymentCardLast4`.
The `newtype` directive on a field names its type instead, `LineItem.quantity => newtype("Quantity")`.
A constraint on an optional field constrains the value inside, so `note: string? where { length(..500) }` is `OrderNote | None`.

A struct is valid when each of its fields is, a container holding a checked type checks nothing again, and there is no validation that walks a model.
A message is the type, the field when the type carries one, the constraint as written, and a detail, `LineItem.quantity: min(1): got 0`, and never echoes a string's or bytes' contents, as in Go.
It cannot carry the path a container would prefix, for the reason [java-backend.md](java-backend.md#constraints) gives: the `LineItem` was built before any `Order` held it.

| Constraint | Checks |
| --- | --- |
| `min`, `max` | An integer, a float, or a `Decimal`, compared; a float that is NaN fails both |
| `length` | A string's characters, or the length of bytes, a list, a set, or a map; an integer means exactly that length |
| `matches` | A string, unanchored, through `re.search` |
| `oneOf` | A value equal to one argument, when another constraint keeps it from being a `Literal` |
| `unique` | A list's elements, through their hash |

`len` on a `str` counts code points, which is what `emit.Length` defines, so a string's length needs no conversion.
An argument to `oneOf` that fails another constraint on the same type warns and is left out, since it could never be held.

### Patterns

`matches` is not passed through as written, because Python's `re` differs from RE2 in three ways that change what a pattern accepts.
`\d`, `\w`, `\s`, and `\b` are Unicode-aware in a `str` pattern, so `\d` matches `٣`.
`re` has no `\p` at all, so `\p{Greek}` is an error when the module loads.
`$` matches before a trailing newline, so `^[a-z]+$` accepts `"abc\n"`, which RE2 refuses.

The backend parses the pattern with `emit.Pattern` and prints the tree in `re` syntax.
`\d`, `\w`, and `\s` become explicit ASCII sets, and `\b` and `\B` become `(?a:\b)` and `(?a:\B)`, a scoped ASCII flag `re` accepts since 3.7.
A Unicode class, general category or script, is printed as the ranges `regexp/syntax` parsed it into, so `\p{Greek}` works with no third-party engine, at the cost of a long class in the generated source.
A case-folded literal is printed as the class of its folds, from `unicode.SimpleFold`, so `(?i)k` matches the Kelvin sign as RE2's does.
End of text is `\Z`, beginning of text is `\A`, and the line anchors are `(?m:^)` and `(?m:$)`.
Inside a class, `[`, `&&`, `--`, `~~`, and `||` are escaped, since `re` reserves them for set operations and warns on them today.

Each pattern is compiled once, in a module-level constant beside the type that uses it.
A pattern RE2 refuses warns at generation time and its type is emitted without the check.

`re` backtracks where RE2 runs in linear time, so a pattern such as `(a+)+$` takes exponential time on a hostile string.
The backend cannot make `re` linear, and [Open questions](#open-questions) weighs an opt-in to the `google-re2` binding.

## Identity

`key(id)` on an entity is a method returning the field:

```python
class User:
    def key(self) -> UserId:
        return self.id
```

A key naming several fields returns a frozen dataclass declared beside the entity, so a consumer can write `dict[LineItemKey, LineItem]`:

```python
@dataclass(frozen=True, slots=True)
class LineItemKey:
    order: Order
    sku: Sku
```

A method and a field share a Python class's namespace, so an entity with a field named `key` warns and is emitted without the method.
A key field reaching a map, by the rule under [The type mapping](#the-type-mapping), warns, since the key could not be hashed, and so does a key class named like a declaration; the entity is emitted without its key.

## Generics

A type parameter keeps its spelling, in PEP 695 syntax, so `Page<T>` is `class Page[T]`.
The checker infers each parameter's variance from how the parameter is used, so nothing is written for it, and a frozen `Page[Order]` is a `Page[Auditable]` when `Order` satisfies `Auditable`.

`requires` is a bound, which the checker enforces on the type itself:

```python
@dataclass(frozen=True, slots=True, kw_only=True)
class Envelope[T: Auditable]:
    body: T
    received_at: datetime
```

So `Envelope[int]` is a checker error, where Haskell and Go can only warn that a consumer can build one.
PEP 695 takes one bound, so a parameter requiring two classes is bound to a protocol the module declares for the pair, `class _AuditableArchived(Auditable, Archived, Protocol)`, which every type satisfying both satisfies (see [Classes](#classes)).

A parameter of a higher kind, `f` in `Collection<f, T>`, has no Python spelling, since a type parameter is always a type.
It warns at the parameter and skips its declaration, and `emit.Cascade` skips what names it.
A parameter of kind `unit` waits on [Units](#units).

## Classes

A class is a `typing.Protocol` whose superclasses are the classes it requires, and whose members are read-only properties for the fields it declares:

```python
class Auditable(Timestamped, Protocol):
    @property
    def created_at(self) -> datetime: ...
    @property
    def updated_at(self) -> datetime: ...
```

A satisfying type writes nothing: a protocol is structural, and a frozen dataclass field satisfies a read-only property, so `Order` is an `Auditable` to both checkers because it has the fields.
The compiler refuses a satisfying type that lacks one of its class's fields, conditional instances included, so every type the model says satisfies a class does.

The protocol is not listed as a base, though listing it would record the conformance the model declared.
Pyright refuses a dataclass field overriding a property of a base it lists, and declaring the member as an attribute instead makes it settable, which no frozen dataclass satisfies, so a listed base would fail one checker or the other.
A protocol declares only the fields its own class declares, not those of a class it requires.

Because a protocol is structural, a bound accepts any type with the fields, which is wider than the model, since the model names its satisfying types.
It is also what lets the instances a base list could never carry satisfy a bound:

| Case | Result |
| --- | --- |
| A satisfying struct in this model, or an instance for another package's type or a prelude type | Satisfies the protocol when it has the fields, which the compiler guarantees |
| A conditional instance, `instance <T> Auditable<Page<T>> requires Auditable<T>` | `Page[T]` satisfies the protocol for every `T`, not only the ones the condition names; warns |
| A class with no fields, such as the spec's `Archived` | An empty protocol, which every type satisfies, so a bound on it narrows nothing; warns at the class |
| A class with several parameters | A generic protocol over all but the first, `class Projection[To](Protocol)`, which constrains a parameter only where a field's type mentions it; warns when one does not |
| A functional dependency | Dropped silently, since the compiler already allowed one instance per determining type |
| A class requiring associated types | Emitted without them; warns |
| A class of arrow kind | Skipped |
| A class reaching itself through what it requires | Skipped |

The plan is `emit.PlanInterfaces`, which Go, C#, and Rust read too, for which classes are generated and which are cyclic; Python's `InterfaceRules` decides the rows above.
`Entity` is the prelude's and has no fields, so it would be an empty protocol; `requires Entity<T>` and `class Auditable requires Entity` warn and are emitted without it, as in Go.

## Units

Python carries no unit in a type that its checker can reduce.
Until phase 6 of the plan, a unit-typed field is its base type with a warning, and the declaration is emitted.
That phase decides between a nominal type per unit and base, which keeps `decimal<kg>` from being passed as `decimal<m>` but drops the unit at the first arithmetic, and `Annotated` metadata, which a consumer's library can read and no checker enforces.

## Serialization

Without a directive, the output carries no serializer: a dataclass is what `dataclasses.asdict` and every Python serializer already read.

`json("pydantic")` on the target block makes the output read and write the JSON wire convention, the one [schema-backends.md](schema-backends.md) describes and the TypeScript and JSON Schema backends write, through Pydantic 2.11 or later, the release that added the alias settings below:

| Construct | Under `json("pydantic")` |
| --- | --- |
| A struct, a variant, a wrapper newtype | `pydantic.dataclasses.dataclass` instead of the standard decorator, so construction also checks every field's type at runtime |
| A field whose Python name differs from the model's | `Field(validation_alias="createdAt", serialization_alias="createdAt")`, with `validate_by_name`, `validate_by_alias`, and `serialize_by_alias` set in the dataclass config, so the constructor keeps the Python name and the wire reads and writes the model's |
| `T?`, `T? \| null` | left out of the output when `None` or `UNSET` respectively, by a wrap `model_serializer` on the dataclass that drops only those fields, so a `T \| null` field still writes `null` |
| A fieldless enum | its `StrEnum` values, which are the tags already |
| A fielded enum | `Annotated[Card \| Cash, Field(discriminator="kind")]`, with a `kind: Literal["Card"]` field defaulted to its tag on each variant |
| A subclass newtype, a checked type | `__get_pydantic_core_schema__`, decoding the base and calling the constructor, so a decoded value was checked |
| `bytes` | base64, from the dataclass config |
| `instant` | `AwareDatetime`, so a decoded or constructed instant without an offset is refused |
| `decimal`, `uuid`, `instant`, `duration` | Pydantic's defaults, which are the convention's strings: a decimal as a string, a hyphenated UUID, RFC 3339, and ISO 8601 |

The discriminant and each variant's tag come from `emit.Discriminant` and `emit.Tag`, so `Card` is `{"kind": "Card", "last4": "4242"}` whatever `name` says, and `discriminant("type")` on an enum or the target block renames `kind`.
A variant field named like the discriminant warns and the enum is skipped, as in Go.
Because a checked type decodes through its constructor, a model decoded from JSON is valid by construction, and Pydantic's `ValidationError` names the violation, which arrived as a `ValueError`.

`json` takes its library as an argument so another could follow, as C#'s does; `pydantic` is the only value, and any other warns.

## Foreign types and externs

`foreign("pendulum", "DateTime")` maps a declaration or a primitive to a class another module declares, imported as `import pendulum as _pendulum` and written `_pendulum.DateTime`.
Two arguments, the module and the name, keep the shape `foreign` has in every backend.
A `where` constraint on a foreign type warns, since the backend does not know what the type holds, and so does a `key`.

An extern resolves through its dependency's `python` target block: the module is that block's `module` directive or else the dependency's package.
TDL's import graph has no cycles, so neither does the generated modules' import graph.
An extern with neither a `foreign` mapping nor a `python` block on its dependency warns and is skipped, and so is each declaration naming it.

## Directives

The backend declares all of these in its handshake.

| Directive | On | Does |
| --- | --- | --- |
| `module("acme.billing")` | the target block | the module's import path, and so its directory |
| `json("pydantic")` | the target block | the serialization under [Serialization](#serialization) |
| `discriminant("type")` | an enum or the target block | the tag property under `json` |
| `width("unchecked")` | the target block | writes the fixed-width integers as plain `int` |
| `name("Account")` | a declaration, field, or variant | the Python identifier, without renaming the model |
| `newtype("Quantity")` | a constrained field | the name of the type carrying its constraint |
| `foreign("pendulum", "DateTime")` | a declaration | the module and name it maps to |
| `key(order, sku)` | an entity | the fields identifying it |
| `prefix` | an enum or the target block | writes variant classes with the enum's name in front |

A directive the backend does not declare is a compiler warning and is passed through anyway.

## Names

| Name | Spelling | Example |
| --- | --- | --- |
| Class, variant class, protocol | last segment, first letter upper-cased | `LineItem`, `Card` |
| Field, property | `emit.Snake` | `createdAt` is `created_at` |
| Fieldless enum member | `emit.ScreamingSnake` | `Draft` is `DRAFT` |
| Type parameter | as written | `T` |
| Field type | the struct, then the field in Pascal case | `LineItemQuantity` |

A class keeps its spelling beyond the first letter, so `HTTPServer` stays `HTTPServer` and a consumer can find it from the model.

A field spelled like a Python keyword gets `_` appended, as PEP 8 suggests, so `class` is `class_`, and so does a class or variant spelled `None`, `True`, or `False`; a soft keyword such as `match` or `type` is a valid name and is left alone.
An escaped name is still the model's spelling on the wire, under `json`.

Some collisions Python would accept silently, by letting the later definition win, and each warns and skips its declaration, which `name` resolves:

- two fields with one snake-case spelling, as `userID` and `user_id`;
- a field type, key class, or variant class named like a declaration or another generated class;
- a declaration whose name starts with `_`, which the module's aliases own, or named like something the module declares for itself: `Unset`, `UNSET`, `Int32`, `Uint32`, `Int64`, `Uint64`, or `ValueError`.

## Deprecation and documentation

A doc comment becomes a docstring on the class, and an attribute docstring, the string literal after the field, on a field or enum member, which Pyright's hover and Sphinx both read.

A deprecated declaration or variant class gets `@warnings.deprecated("reason")`, so the checker reports each use and constructing one warns at runtime.
Python has no deprecation for a dataclass field or an enum member, so a deprecated one carries its reason in its docstring only.

## Diagnostics

These warn with the node's position, and the declaration reaching one is skipped: an extern with no mapping, a higher-kinded parameter, a set element or map key reaching a map, a variant field named like the discriminant under `json`, and a name collision.
`emit.Cascade` then skips every declaration naming a skipped one.

These warn and the declaration is still emitted: a unit until phase 6, a `matches` pattern RE2 refuses, a `where` constraint the backend gives no meaning to, a `oneOf` argument another constraint excludes, a default that fails its field's check, a default on a foreign type, a conditional instance, a class with no fields, a class's associated types, a `requires` naming `Entity`, and a `key` it cannot generate.

An error stops the run, and only a module path Python refuses earns one.

## Checking the output

The tests run `mypy --strict --enable-error-code=exhaustive-match` and Pyright in strict mode over every response, and import it under `python3`, when each is on `PATH`.
Both checkers, because consumers use both and they differ where this output leans on them: Pyright refuses a dataclass field overriding a protocol's property, which mypy accepts, and reports a `default_factory=dict` as partially unknown, so the output writes `dict[str, str]`.
`checks.gen-python` always does, over `testdata/gen/smoke`, with `python313`, `mypy`, `pyright`, and `pydantic` from nixpkgs, and runs it a second time with `json("pydantic")`.

The backend runs no formatter, but its fixed layout is the one `ruff format` writes, and `checks.gen-python` runs `ruff format --check` and `ruff check` so the two stay in step.

## Reverse

An importer is feasible, as it is for TypeScript: Python's own `ast` module parses Python, so an embedded `outline.py` run under `python3` can write the JSON outline `reverse.go` reads, as `outline.js` does under `node`.
It is not in this plan's phases; [reverse-plan.md](reverse-plan.md) orders the importers.

## Overlap with other targets

| Piece | Shared with | Where |
| --- | --- | --- |
| The class plan and cycle refusal | Go, C#, Rust | `emit.PlanInterfaces` |
| The wire convention, `kind` and tags | TypeScript, JSON Schema, OpenAPI, Go, C#, Rust | `emit.Discriminant`, `emit.Tag` |
| `length` counted in code points | Every backend that validates | `emit.Length` |
| The RE2 check | Every backend that validates `matches` | `emit.Pattern` |
| A small range or `oneOf` as a literal union | TypeScript | `backend/typescript/narrow.go` |
| Refusing a value at construction, no `validate` | Rust, Java | design only |
| One module per model, unprefixed variants in its namespace | Haskell | design only |

The literal-union rule lives in the TypeScript backend; whichever of the two is built second moves it into `backend/internal/emit`, so both narrow the same constraints.

Rust, Java, .NET, and Python each print a `regexp/syntax` tree in their own dialect.
[rust-backend.md](rust-backend.md#overlap-with-other-targets) puts the walk in `backend/internal/emit` with a table per engine for whichever is built first, and Python fills in a table.
Python's table is the only one that prints Unicode classes as ranges, since `re` is the only engine with no `\p`.

## Open questions

- **Runtime-checked structs.** A `__post_init__` on every struct could check each field's type and constraints, so a struct built by unchecked code still refuses a violating value. It would check what the checker already proved on every construction, which is the cost the type-first design avoids; `json("pydantic")` already does it at the boundary where unchecked data arrives.
- **Linear-time patterns.** A `regex("re2")` directive could compile patterns with the `google-re2` binding, which runs RE2 itself, so `matches` would mean exactly what `emit.Pattern` checked and a hostile string could not make it slow. It is a native dependency the default output avoids.
- **An immutable map.** If the standard library gains a `frozendict`, a map could be hashed with the rest of its struct.
- **A runtime module.** A published `tdl` package would hold `Unset`, the `ValueError` helper, and the protocols for `Entity` and units, so they cross generated modules. It is a package the project would version and publish, which Rust's design also weighs.
- **Lists as sequences.** `Sequence[T]` would accept a caller's `list`, which is more convenient to build, at the cost of a struct's hash failing when it holds one.
- **A dependency-free codec.** Generated `to_json` and `from_json` functions over the standard `json` module would carry the wire convention without Pydantic, at the cost of a second serializer to keep in step with the convention.
